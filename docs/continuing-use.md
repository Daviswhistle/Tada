# 기록을 이어 쓰는 지속 사용

설정 → 연결된 계정의 **지속 사용 켜기**는 `continuing_conversation_24h_v1` 동의다. 기존 기록의 평생 64회 제한을 몰래 초기화하지 않고, 같은 계정·모델·자료 범위에서 최근 24시간 최대 64회 요청을 허용한다. API 결제나 공급자를 바꾸지 않는다. 한 번 맡긴 일은 여러 모델 요청을 쓸 수 있고, 공급자 자체 사용 제한도 별도로 적용된다.

새 정책은 직접 대화와 이미 허용된 수시 확인(v2)에 적용된다. 옛 하루 확인(v1)과 일회성 로컬 review는 기존 평생 한도를 유지한다. 수시 확인의 시간당 한 번·하루 네 번·확인당 네 요청 제한도 유지한다. 최근 24시간 잔여량이 네 회 이하면 새 자동 판단을 중지해 직접 대화에 남긴다. 모델 없는 일정 관측·알림은 계속된다.

각 모델 요청을 예약할 때 현재 잔여량을 다시 판정한다. 처리 도중 지난 요청이 24시간 창에서 빠지면 새 여유를 사용할 수 있고, 아직 만료되지 않았다면 다음 호출을 중지한다.

최초 선택 시 시각이 없는 기존 마지막 64개 요청은 모두 선택 시각에 사용한 것으로 보수적으로 계산한다. 요청 예약과 시각 영수증은 같은 SQLite 트랜잭션으로 저장한다. 실패·취소·결과 불명 요청도 사용량을 차지한다. 재시작이나 켜기/끄기로 사용 여유를 초기화하지 않으며, 시계가 뒤로 가도 저장된 시각보다 과거로 창을 옮기지 않는다. 누적 요청·토큰·불명 결과 원장은 그대로 보존한다. 정책을 켠 기기의 접근이 해제되거나 만료되면 정책도 비활성화된다. 설정 화면에서 잔여 요청과 다시 가능한 시각을 확인한다.

지속 사용 중에는 대화 1,000개와 과거 제안·review 누적 1,000개 때문에 더 이상 새 일을 접수하지 못하는 제한을 적용하지 않는다. 동시 접수 16개, 미결 제안 32개, 예약 review 32개, 진행 중 업무 1,000개 등 현재 작업량 제한은 남는다. 과거 기록은 삭제하지 않는다. 사용자가 지속 사용을 끄면 옛 한도로 돌아가며 이미 저장한 기록은 보존된다.

## 기억과 과거 근거

모델에 보내는 최근 문맥은 공급자의 실제 직렬화 크기로 측정한다. 오래된 완전한 대화 묶음부터 덜어내며, 도구 호출과 그 응답을 중간에서 자르지 않는다. 현재 요청의 진행 중 도구 묶음은 그대로 유지한다. 원본 대화와 결과는 암호화 저널에 남는다. 한 번의 요청 자체가 너무 크면 여전히 문맥 한도에 도달할 수 있다.

비서는 `search_history`와 `read_history`로 같은 저널의 과거 내용을 조회할 수 있다. 검색은 한 페이지 최대 100개 기록을 확인하고 최대 5개 발췌와 다음 커서를 반환한다. 결과가 불완전하면 다음 페이지가 필요함을 표시한다. 중단·취소 상태도 함께 반환하며 과거 지시를 새 실행 권한으로 취급하지 않는다. 원문 중 일부만 반환한 경우 이를 표시하고, 저장 문서는 `read_document`로 별도 조회한다.

수시 확인(v2)도 지속 사용이 켜져 있으면 이 조회 경로를 공유한다. 새 메일의 주제와 관련된 과거 취소·완료·선호를 찾아 제안에 반영할 수 있다. 옛 하루 확인이나 로컬 review 권한을 확대하지 않으며, 자동 확인의 읽기 전용 범위와 모델 호출 한도는 유지한다.

문맥에서 빠진 저장 문서를 다시 읽으면 호스트가 그 문서의 실제 저장 근거만 복원한다. 모델이 임의로 만든 출처 ID나 다른 근거로 바꾼 ID는 거절한다. 원래 전역 출처 번호는 재사용하지 않는다. 저장 문서를 바탕으로 수정한 결과는 `saved_document_sources_checked`로 표시하며, 예전 자료를 지금 다시 조회한 것으로 주장하지 않는다. 현재 외부 사실이 필요한 요청은 현재 자료를 다시 읽어야 한다.

지속 사용을 꺼도 이미 압축된 문서의 근거를 복원할 수 있다. 이때는 기존 모드대로 출처를 다시 확인하며, 저장 시점의 근거만으로 현재 자료 검증을 통과시키지 않는다.

Google 자료 범위는 최근 7일 받은편지함·앞으로 7일 기본 캘린더 각 최대 20개로 동일하다. 문맥이 충분한 공급자에서는 목록에 최대 24 KiB, 전체 Google 도구 결과에 최대 48 KiB를 허용하되 실제 요청 예산이 우선한다. 작은 문맥에서는 기존 작은 한도를 유지한다. 관측된 발췌를 재검증할 때도 정확히 같은 범위와 항목 수로 비교한다. 큰 공급자를 쓰면서 두 메일만 보게 되던 고정 문맥 병목을 줄이는 변경이며, 모든 메일을 검토한다는 보장은 아니다.

## 보존과 검증 범위

v1–v5 SQL 문자열과 기존 암호화 형식은 그대로다. 정책은 v5의 암호화 설정으로 저장하며 이를 모르는 구버전 앱은 거절한다. 수동 DB 편집이나 자동 마이그레이션은 필요 없다. 사용량은 SQL 집계로 읽고 문서 목록과 과거 검색은 제한된 페이지를 읽는다.

회귀 검증은 24시간 경계·시계 역행·재시작·토글·unknown 과금, 구버전 한도 보존, 1,000개 이후 접수, 제한된 기록 검색, 실제 문맥 크기에 따른 정리, 도구 응답 쌍 보존, 저장 문서의 근거 복원과 위조 거절, 인증된 설정 API를 포함한다. 합성 모델 시험은 실제 모델의 기억·판단 품질이나 출시 합격을 대신하지 않는다.

## 직접 편집한 문서에서 이어가기

저장 문서의 **직접 수정**에서 제목·본문을 고치고 새 버전으로 저장할 수 있다. 이전 버전과 같은 문서 계보를 유지하며 원본을 덮어쓰지 않는다. 직접 저장은 모델 요청·대화 checkpoint·업무 권한을 변경하지 않는다. 이후 비서가 수정할 때는 해당 요청에서 최신 문서를 실제로 읽어야 한다. 작성 중 다른 기기에서 새 버전이 생기면 저장을 거절하고 양쪽 내용을 비교하도록 한다. 저장 응답이 불확실할 때에는 동일 요청의 결과만 확인하며 자동으로 새 저장을 만들지 않는다.

작성 중인 초안은 화면 갱신과 편집창 닫기 동안 유지되지만 브라우저 종료·새로고침 뒤 복구되는 영구 초안은 아니다. 종료 전에 경고한다. 최신 버전으로 전환하면 전환 전 초안을 같은 창에 남긴다. 여러 번 충돌해도 각 초안을 유지하며 재열기·저장 뒤에도 명시적으로 지울 때까지 종료 경고 대상에 포함한다. 필요한 내용을 옮긴 뒤 **보관 초안 지우기**로 정리할 수 있다. 문서 한 개의 본문 한도는 기존과 같은 UTF-8 4KiB다. 수정한 본문·제목은 자료이며 새로운 행동 권한이 아니다. 이전 출처는 역사적 참고 자료로만 이어받고 소유자가 추가한 사실이 검증됐다는 뜻으로 표시하지 않는다. 비서가 직접 수정한 내용만 다듬을 때에는 무관한 옛 출처를 억지로 인용하지 않아도 된다. 실제로 인용한 참고 자료는 기존 검증을 거친다.

이 기능은 DB v5에서만 제공하며 SQL 스키마를 바꾸지 않는다. 소유자 편집은 기존 암호화 답변 안의 문서 메타데이터 **v2**(`author: owner`)로 구분한다. 비서 문서 v1은 그대로 읽는다. **v2 문서를 한 번 저장한 기록은 이를 모르는 구버전 실행기로 열 수 없다.** 구버전은 복구 작업 전에 문서 버전을 거절한다. 과거 버전으로 되돌리려면 v2 저장 전 백업이 필요하며 앱은 기록을 자동 변환하거나 삭제하지 않는다.

## 중단한 요청에서 이어가기

비서는 이전 대화를 읽을 때 저장된 완료 여부, 중단 이유, 해당 요청의 확인된 모델 응답과 확인되지 않은 요청 수, 현재 요청의 남은 사용 한도를 함께 볼 수 있다. 이 정보는 실제 기록에서 계산하며 과거 답변의 주장을 실행 증거로 취급하지 않는다. 재시작은 진행 중인 요청을 중단·미확정 상태로 남기고 자동으로 재전송하지 않는다. 사용자가 다시 부탁하면 마지막으로 저장된 문서와 현재 수정본을 확인해 필요한 작업을 이어갈 수 있다. 취소한 다른 일과 이전 사용량은 유지한다.

모델 요청 원장은 메일 발송·상대방 수신 같은 외부 행동의 영수증이 아니다. 중단되기 전 답변 안에서 아직 확정하지 않은 모든 관측·단계가 복원되는 것도 아니다. 이 경로는 저장된 결과에서 이어가는 기능이며, 매 실행의 현재 권한과 사용 한도 검사를 생략하지 않는다.
