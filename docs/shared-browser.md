# 공유한 브라우저에서 입력하기

설정 → 연결된 계정 → 브라우저 작업에서 전용 Chrome을 연다. 필요한 사이트를 연 뒤 탭 찾기에서 제목·주소를 확인하고 **이 탭 읽기와 입력 허용**을 선택한다. 평소 대화에서 문구 작성·입력을 부탁한다. 공유 중인 사이트는 대화 위에 표시되고 바로 중지할 수 있다.

이 경로는 같은 ContactService, 현재 선택 모델, 대화·요청 원장을 사용한다. 자동 메일 확인이나 예약된 로컬 재확인에는 브라우저 도구를 주지 않는다. 공유는 현재 실행·탭·페이지와 공유를 허용한 기기의 요청에 한정한다. 다른 연결 기기에서는 같은 탭을 다시 선택해 공유할 수 있다. 페이지 이동, 브라우저 종료·호스트 재시작 이후에는 다시 공유한다. 기존 다른 브라우저 창의 프로필·쿠키·인증 정보를 가져오지 않는다.

## 지금 처리하는 일

- 공유 페이지의 표시된 본문과 일반 text/search 입력란·textarea를 관측한다. 모델은 호스트가 발급한 관측과 필드 참조만 사용한다. 주소는 origin만 전달하고 query·fragment 등이 든 전체 주소는 정확한 대상 확인을 위한 호스트 내부 정보로 유지한다.
- 입력 직전 같은 문서·URL·요소·라벨·주변 내용·기존 값과 폼 컨트롤 구성·계정 선택·체크 상태를 재확인한다. 모델에서 제외한 필드의 상태도 페이지 내부 사전조건으로만 비교하며 값은 호스트·모델·기록으로 내보내지 않는다. 사용자가 직접 바꾼 값이나 교체된 요소를 덮어쓰지 않는다.
- 한 필드의 값을 변경하고 별도 관측에서 현재 값을 확인한다. 성공 범위는 `textbox_dom_value`다. 사이트의 자동 저장이 발생할 수 있지만 서버 저장·폼 전송 완료를 확인했다는 의미는 아니다. 모델 답변과 별도로 이 범위를 표시한다.
- 비밀번호·숨김 필드, 라벨·접근성 이름·placeholder로 식별한 인증정보 필드와 숨긴 본문을 모델 관측에서 제외하고 비활성·읽기 전용 필드는 입력 대상으로 삼지 않는다. 기본 텍스트 공유에는 iframe, 파일 업로드, 버튼 클릭·Enter 제출, 임의 JavaScript·셸이 포함되지 않는다. 선택 파일 처리는 아래의 별도 권한을 사용한다. 로그인은 소유자가 전용 창에서 직접 한다.

입력은 자동 저장을 유발할 수 있어 `external_write`로 기록한다. 사이트가 텍스트 입력에 연결한 모든 네트워크 동작을 차단하는 기능은 아니다. 로그인·결제·계정 보안 변경이나 다른 사람에게 연락하는 위임은 이 공유에 포함하지 않는다.

## 권한·중단·기록

도구는 current foreground turn, 현재 기기, 공유 epoch를 최종 전송 직전에 확인한다. `DISPATCHING`을 암호화된 동일 SQLite transaction으로 저장한 다음 CDP pipe에 보낸다. 기록과 전송 사이에는 비동기 대기가 없다. Chrome의 isolated world에서 고정된 호스트 코드만 실행하며 페이지 스크립트가 모델 도구나 호스트 참조를 정의할 수 없다.

응답 유실·검증 실패·전송 후 취소는 `UNCERTAIN`, 실제 값 불일치는 `ACKNOWLEDGED / APPLIED_MISMATCH`로 보존한다. 다시 관측하거나 새 turn·새 공유를 만들더라도 같은 origin의 미확정 작업을 자동 재입력하지 않는다. 재시작은 `DISPATCHING`을 `UNCERTAIN`으로 복구하며 어느 입력도 재생하지 않는다. 설정에서 요청했던 필드·값을 확인하고 실제 사이트를 살핀 뒤 새 작업을 허용할 수 있다. 이 소유자 확인은 이전 action을 성공으로 바꾸지 않는다.

기존 v5의 확장 가능한 encrypted settings에 버전 있는 action record·immutable payload·receipt를 개별 보관한다. 기존 v1–v5 SQL schema 문자열과 기록은 바꾸지 않는다. 공개 ActionRecord validator·상태 의미를 재사용하되, 기존 Rust mock-action broker가 이 경로를 중개한다고 주장하지 않는다. contact host가 이 경로의 admission을 소유한다. 최근 결과는 최대 20개만 화면용으로 읽고, 미해결 작업은 별도로 모두 조회한다. 완료 이력을 한도 때문에 지우지 않는다. 한 turn 입력·관측은 각각 최대 8회다. 관측은 최대 40개 입력 필드·본문 12,000자이며 대화의 32KiB와 현재 provider 예산에 맞춰 줄이고 생략을 표시한다. 관측을 갱신하면 이전 참조를 폐기하고, turn 종료·공유 중지 시 페이지 스냅샷을 정리한다.

대상 변경이 입력 전에 확인되면 `CONFIRMED_NOT_APPLIED`와 `observe_current_page`를 돌려준다. 다시 관측한 대상이 원래 의도와 맞을 때만 새 입력을 준비할 수 있다. 미확정 효과·불일치·권한 취소를 재시도로 바꾸지 않는다.

## 실행 환경과 검증 범위

설치된 Chrome/Chromium을 sandbox를 유지한 채 실행한다. 전용 pipe와 새 private profile을 사용하고 실제 페이지는 별도 incognito browser context에만 연다. 마지막 전용 창을 닫으면 공유와 private context·쿠키를 폐기한다. 다시 열기는 새 private context를 만든다. 서비스가 닫히면 소유한 자식 프로세스와 임시 프로필만 정리한다. 디버깅 포트 탐색이나 다른 프로세스 종료는 하지 않는다. Linux/WSLg와 native Windows에서 실제 Chrome 실행 경로를 검증했다. macOS 실행 파일 탐지는 있으나 실행 검증은 아직 없다. 이 실행 경로 시험은 물리 휴대폰이나 로그인한 실제 사이트의 검증이 아니다.

`shared-browser-smoke.mjs`는 sandboxed Chrome·실제 ContactService·합성 모델·loopback 사이트로 값 변경, 자동 저장 발생, 사용자 수정 보존, mismatch, navigation 무효화를 검사한다. 서버의 자동 저장 수신은 평가 사이트가 별도로 관측한 근거이며 제품의 DOM receipt를 서버 검증으로 바꾸지 않는다. 실제 모델의 이해, 임의 사이트, 물리 기기 또는 출시 수락 증거는 아니다.

`shared-browser-boundaries.mjs`는 실제 Chrome에서 계정 select·checkbox 변경, opacity·크기·clip으로 숨긴 필드, 관측 갱신·turn 종료·공유 중지의 스냅샷 정리, 마지막 창 종료 후 새 private context·쿠키 초기화를 검사한다. 실제 모델 첫 A08 실험은 두 변형 모두 화면 변경 뒤 재관측하지 않아 실패했다. 해당 결과와 독립 의미 검수는 `evals/assistant-v1/results/2026-10-09-shared-browser-first*.json`에 보존한다.

같은 고정 조건의 수정 후 실제 선택 구독 실행에서는 두 A08 변형이 독립 의미 검수와 주 세션 수락을 통과했다. 새 화면의 올바른 필드에 입력하거나, 다른 계정 표시를 확인한 뒤 입력 없이 필요한 복귀를 안내했다. 원문과 범위는 [검증 기록](qualification-2026-10-09.md#공유-브라우저의-현재-대상-확인-a08)에 남긴다.

숨겨진 접근성 라벨도 인증정보 판별에 사용하되, 모델용 본문은 가시성 검사를 통과한 텍스트만 제공한다. 공유 중지와 도중 실패는 해당 CDP 세션을 분리한다. 늦게 실패한 이전 공유 요청은 더 새로운 공유를 해제하지 않는다.

폼 내부 이동도 대상 변경이다. 호스트는 각 control의 실제 form 객체를 관측에 고정하고 전송 전과 입력 후에 대조한다. 인증 코드·PIN·카드 보안값을 나타내는 일반 라벨도 제외하며, disabled fieldset 또는 inert 요소 안의 입력은 허용하지 않는다. 임시 프로필 정리는 제한적으로 재시도하고, 실패해도 대화·계정 잠금 정리는 계속 수행한다. 이는 임의 페이지의 모든 민감한 내용을 자동 판별한다는 보장이 아니며 공유 화면은 소유자가 선택한다.

비공개 사전조건에는 페이지의 구조·속성, `baseURI`, 계산된 form action·method도 포함한다. 순회 중 최대 10,000개 노드·20,000개 속성·524,288개 문자열 문자를 검사하며 큰 페이지를 잘라서 쓰지 않는다. 값 변경 뒤 `input` 한 번만 보낸다. `change`·focus·blur·Enter는 보내지 않으므로 이 이벤트에서만 저장하는 사이트의 저장을 유발하지 않는다. 동적 화면은 재관측이 더 자주 필요할 수 있으며 기존 횟수 제한을 유지한다. 이 검사는 관측 가능한 변경을 차단하는 것으로, 사이트 JavaScript의 내부 상태나 자동 저장 계정을 증명하지 않는다.


## 선택한 파일을 고치고 실제 결과 확인하기

탭 선택 화면에서 **선택한 파일 처리도 허용**을 누르면, 그 탭의 파일 입력란에 이미 선택된 작은 텍스트 파일도 현재 대화로 맡길 수 있다. 기존 읽기·입력 공유는 이 권한을 자동으로 받지 않는다. 파일 내용이 현재 선택 AI에 전달되며, 입력란 교체만으로 사이트가 자동 업로드하거나 문서를 열 수 있음을 먼저 표시한다. 현재 범위는 파일당 32KiB 이하의 TXT·CSV·TSV·JSON·Markdown·로그다. 본문을 전부 관측 예산에 담을 수 없으면 생략한 상태로 수정하지 않는다. 임의 로컬 경로·다른 앱의 파일·바이너리 문서 편집은 제공하지 않는다. 숨김 파일과 파일명에 passwords·credentials·secrets·token·개인 키·비밀번호·인증정보로 식별되는 파일은 관측 참조와 본문 읽기에서 제외한다. 모든 비밀 내용을 자동 판별한다는 뜻은 아니다.

비서는 현재 화면과 선택 파일을 읽고 원인을 판단한 뒤, UTF-8 수정본을 같은 입력란에 적용할 수 있다. 모델은 원문에서 정확히 한 번 나타나는 부분만 순서대로 치환하거나, 빈 수정 목록으로 내용 그대로 인코딩을 바꾼다. 전체 재작성은 8KiB 이하 도구 인자에만 허용해 기존 16KiB 모델 응답 한도를 유지한다. 모호한 치환이나 32KiB를 넘는 결과는 실제 입력 전에 거부한다. 자동 처리 사이트에는 별도 제출을 하지 않으며, 제출이 필요한 폼은 관측한 같은 폼의 명시적인 POST 버튼 중 한국어·영어의 파일 가져오기·업로드·열기로 식별되는 버튼만 선택한다. 일반 Submit, 연락·결제·공개·계정 작업을 나타내는 버튼이나 전송값·대상은 참조 발급과 실행에서 제외한다. 폼에는 파일 입력과 표준 CSRF 보호용 숨김 값만 허용한다. 이름 속성이 없어도 값을 제출할 수 있는 알 수 없는 form-associated custom element는 거부한다. 이름 없는 비밀번호·인증 코드 입력도 교체를 차단한다. 버튼 없는 자동 처리도 이벤트 전에 폼의 같은 origin·현재 창 목적지와 제외 작업 여부를 확인한다. 퍼센트 인코딩된 한글·영문 목적지도 제한된 단계로 해석해 검사하며, 해석할 수 없는 주소는 실행하지 않는다. 같은 폼의 다른 선택 첨부에도 작은 텍스트·파일명·가시성 조건을 적용한다. 인증정보·PDF 등 지원 밖 파일, 숨긴 첨부나 한 입력란의 다중 첨부가 있으면 교체 이벤트부터 차단한다. 다른 이름 있는 전송 필드가 있으면 파일을 읽을 수는 있지만 교체 이벤트나 제출을 실행하지 않는다. 숨긴 operation·수신자 값이 파일 공유를 다른 업무 권한으로 바꾸지 못하게 하는 제한이다. input 이벤트 직후와 change 이후 제출 직전에 같은 사전조건을 확인한다. 페이지 문맥·구조·속성·파일 또는 제출 의미가 변하면 후속 이벤트와 제출을 멈춘다. 입력란이 이미 바뀐 사실은 불확실 효과로 보존한다. 이 제한은 사이트 내부 JavaScript의 모든 외부 효과를 차단하는 네트워크 격리 기능이 아니다. 같은 origin, 현재 계정·다른 입력값·폼 대상·공유 epoch·기기·현재 요청을 확인한다. 모든 File 객체와 개수를 고정하며, 같은 이름의 다른 파일로 바꾸면 제출하지 않는다. 파일 이벤트 뒤에도 컨트롤 객체의 순서를 다시 확인한다. 파일 이벤트 뒤 제출 버튼의 전송값과 표시문구도 다시 확인한다. 선택 파일은 덮어쓰지 않는다. 원본 바이트와 수정본, 의도와 실행 상태를 동일 암호화 원장에 먼저 저장한다. 설정의 브라우저 작업에서 두 파일을 따로 내려받을 수 있다. 로그인·결제·계정 변경·다른 사람에게 연락할 권한은 추가되지 않는다.

파일 교체나 제출의 응답만으로 완료를 주장하지 않는다. `submitted`는 브라우저의 실제 submit 이벤트 관측 여부다. 필수 입력 검증에 막히면 `form_validation`, 이벤트를 확인하지 못하면 `submission_not_observed`를 반환하며 업로드를 다시 시도하지 않는다. 적용 응답을 확인한 작업에만 현재 대화의 비공개 결과 참조를 발급한다. 응답을 잃었거나 제출을 관측하지 못한 작업은 다운로드만으로 성공으로 바꾸지 않는다. 비서는 다시 화면을 관측하고, 적용한 File 객체가 같은 입력란에 유지되는 동안 적용 전에는 없었던 네트워크 주소를 가진 같은 origin의 다운로드 링크를 읽어 실제 바이트와 수정본을 비교한다. 이전부터 있던 같은 다운로드 주소는 요소가 복제·재생성돼도 검증 대상으로 쓰지 않는다. download 속성이 없는 일반 링크와 숨겼거나 표시 목록 20개 밖에 있던 링크도 비공개 사전조건으로 포함하며, 모델에는 보이는 제한된 목록만 전달한다. 원본 파일이 사라져 적용 전에 읽지 못하면 명확한 미적용 실패로 기록한다. 임의 URL과 리다이렉트는 허용하지 않는다. 제출 버튼과 다운로드의 title 툴팁도 목적 검사에 포함한다. 다운로드 주소·표시·접근성 라벨도 연락·결제·계정 변경 등 제외 의미를 검사하며, 참조 발급과 GET 직전에 재검사한다. `selected_file_download_v2`는 `selected_file_download_observation` 영수증 v3에 다운로드 바이트만 기록한다. 주소가 달라도 기존 파일일 수 있으므로 일치·불일치 모두 외부 효과는 UNCERTAIN, 서버 적용·보관은 not_checked로 유지한다. 다운로드만으로 VERIFIED나 APPLIED_MISMATCH로 승격하거나 같은 사이트의 재실행 차단을 풀지 않는다. 과거 v1/영수증 v2 기록은 읽을 수 있지만 새 실행은 그 완료 경로를 사용하지 않는다. 문서 열기나 가져오기의 성공은 앱 화면의 실제 결과도 확인해야 한다. 사이트가 다운로드를 제공하지 않거나 페이지 이동으로 공유가 끝나면 자동 검증을 마칠 수 없다. 불확실·불일치 효과는 보존하고 같은 사이트에 다시 쓰지 않는다. 읽기 검증을 재시도하는 것과 업로드를 반복하는 것은 다르다.

도구는 관측한 대상에 맞춰 단계적으로 노출한다. 처음에는 화면 관찰, 관측 후에는 해당 입력·파일 읽기, 파일을 읽은 뒤에는 수정, 적용 후 새 다운로드를 관측하면 검증이 가능하다. 연결된 Google 도구와 함께 사용할 때의 문맥 부담을 줄이도록 설명과 노출량을 줄였으며, 기본 로컬 모델 한도나 공급자는 바꾸지 않는다. 읽기를 허용하기 전에 다음 단계의 도구 스키마와 시스템 문구까지 포함한 요청 전체를 계산한다. 파일 크기 상한 안에서도 전체 문맥에 담을 수 없는 파일은 작업할 수 없으며, 읽기 참조를 철회하고 도구 오류로 반환해 대화를 이어갈 수 있게 한다.

텍스트 작업의 v1 grant/action은 그대로다. 파일 작업은 별도 grant와 v2 encrypted action envelope를 사용한다. 기존 SQL schema나 Rust ActionRecord 의미를 바꾸지 않는다. v1/v2 기록을 함께 읽고 백업·복원하며, 복원된 기록은 과거 증거일 뿐 실행 권한이 아니다. 파일 작업을 모르는 이전 앱은 v2 기록을 해석하거나 재실행하지 못한다. 예전 앱으로의 다운그레이드는 지원하지 않는다. 공유 ActionRecord의 파일 작업 예시는 양쪽 runtime fixture에서 검증한다.

`shared-file-smoke.mjs`는 실제 sandboxed Chrome 파일 선택, 실패한 UTF-16 CSV 업로드, UTF-8 복사본 제출, 실제 HTTP 다운로드 바이트 일치, 원본 디스크 바이트 보존을 검사한다. 관측 후 계정 변경은 적용 전에 멈추며, 다운로드 리다이렉트는 따라가지 않는다. 모델은 사용하지 않는 실행 경로 검사다. 이 실행 경로 시험을 제품 수락으로 계산하지 않는다. 이후 실제 선택 모델의 A02/A03 고정 변형 결과와 독립 의미 검수는 [2026-10-10 검증 기록](qualification-2026-10-10.md)에 남겼다.

2026-10-10 최종 작성자 검증: 네이티브 읽기 중개기를 지정한 전체 `npm run check` **1,429개(생략 없음)**, Native Windows 관련 **270개(생략 없음)**, 양쪽 실제 sandboxed Chrome 파일 시험을 통과했다. Windows 시험 복사본은 실행 뒤 전체 소스 바이트 일치도 확인했다. 최신 공유 fixture를 JavaScript와 Rust 계약 검사에서 모두 확인했다. 이 단위에서 `npm ci --ignore-scripts`, Rust fmt·clippy·workspace·`tada-agentd` process-fixture를 이미 통과했으며 이후 Rust 구현·공유 스키마·의존성은 변경하지 않았다. 실제 모델 의미 평가와 출시 수락은 별도다.

회귀 검사는 버튼·목적지·계정·다른 첨부·컨트롤 순서의 변경, input/change 사이 변경, 숨은 명령과 인증 입력, 알려지지 않은 form control, 연락·결제·계정 목적지, 위험한 다운로드 GET, 원본 삭제, 응답 유실과 기존 결과 재사용을 포함한다. 새 query 주소에서 기존 같은 파일을 내려받아도 업로드 0회·UNCERTAIN·재실행 차단 유지임을 실제 Chrome에서 확인한다. 전체 파일을 8KiB 인자에 다시 쓰지 않아도 되는 20KB 인코딩·부분 수정과, Google·지속 사용을 함께 켠 기본 로컬 문맥 한도도 검사한다.

독립 검토에서 발견한 반례를 수정하면서, 앞선 hash-only 완료 판정은 폐기했다. 완전하지 않은 CDP 본문이나 시간 근접성을 업로드 인과관계로 해석하지 않는다. 현재 파일 도구는 수정본 생성·선택 파일 교체·다운로드 비교를 제공하며, 사이트 적용의 자동 확정은 제공하지 않는다. 소유자는 실제 사이트 상태를 확인한 뒤 새 작업을 허용할 수 있다. 그 확인도 과거 작업을 성공 기록으로 바꾸지는 않는다.

답변에는 소유자 인증이 필요한 원본·수정본 다운로드 링크를 함께 저장한다. 최근 설정 목록에서 밀려나도 대화의 해당 답변에서 다시 받을 수 있으며 재시작·백업 복원 뒤에도 유지된다. 정확한 파일 다운로드 경로만 클릭 가능한 상대 링크로 허용하고, 다른 API·query·fragment·상위 경로는 허용하지 않는다. Telegram에는 컴퓨터 대화에서 받을 수 있다는 안내를 전달하며 휴대폰 파일 전송으로 표시하지 않는다.

대화 다운로드 링크는 실제 Chrome의 1,100px·390px 화면에서 가로 넘침 없이 표시되며 최소 44px 높이로 누를 수 있다. 이는 브라우저 레이아웃 확인이고 실제 휴대폰 송수신 검증은 아니다. Windows 전체 검증 뒤 바꾼 CSS는 다시 복사하고 전체 소스 바이트 일치를 재확인했다.

## 다음 대화에서 저장한 파일 다시 찾기

지속 대화 사용을 켜 두면 `list_saved_files`와 `read_saved_file`로 과거 파일 작업의 원본·수정본을 다시 찾고 읽을 수 있다. 브라우저 공유를 다시 켤 필요는 없다. 최근 화면용 20개 제한과 무관하게 오래된 기록을 조회하고, 재시작·백업 복원 뒤에도 기존 인증 다운로드 주소를 제공한다. 현재 파일 목록이나 사이트의 적용 결과를 새로 관측했다는 뜻은 아니다. 복원본에는 원래 기록 세대와 격리 상태를 표시하며 어떤 작업도 다시 실행하지 않는다.

호스트는 한 조회에서 최대 100개의 암호화된 작업을 검사한다. 파일이 없는 페이지도 다음 커서가 있으면 계속 찾는다. 도구 응답은 최대 5개 파일 쌍을 반환하고 작은 문맥에서는 항목을 줄여 다음 페이지로 넘긴다. 현재 원장의 갱신 순서 뒤에 복원 기록의 고정 키 순서를 이어 읽으며 전체 생성 시각순 목록이라고 보장하지 않는다. 복원 기록은 가벼운 키 인덱스와 개별 조회를 사용해 페이지마다 전체 파일 본문을 복제하지 않는다.

커서와 파일 읽기 참조는 현재 요청에만 유효하다. 원장 작업 기록이 바뀌면 이전 페이지 커서는 폐기하고 처음부터 조회한다. 같은 상태·같은 rowid를 유지한 영수증 갱신도 포함한다. 조회 시와 모델 전송·답변 수락 전에 현재 요청, 기기, 지속 대화 설정의 변경 여부를 확인하므로 껐다 다시 켜도 이전 권한은 살아나지 않는다. 지속 대화 사용 중지는 소유자가 기존 다운로드 링크를 직접 여는 권한까지 취소하지 않는다.

본문은 기존 32KiB 파일 상한과 현재 문맥 예산 안에서 완전히 읽거나 명시적인 오류로 돌려준다. BOM이 있으면 UTF-16을, 그 외에는 UTF-8을 시도하며 다른 인코딩은 근거를 갖고 지정해야 한다. 내용을 조용히 자르거나 잘못된 문자를 대체하지 않는다. 이후 대화용 체크포인트에는 다시 읽으라는 짧은 안내만 남기며 파일은 기존 암호화 원장에 보존된다. SQL schema·백업 형식·파일 작업의 UNCERTAIN 상태와 재실행 차단 의미는 바꾸지 않는다.
