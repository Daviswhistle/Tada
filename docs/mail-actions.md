# 대화에서 메일 준비하고 보내기

대화에서 메일을 부탁하면 초안이 같은 대화에 저장된다. **메일 초안·발송 결과 확인**에서 계정, 받는 사람, 참조, 숨은 참조, 제목과 본문을 확인·수정한다. 수정은 먼저 저장해야 하며, **이 내용으로 보내기**가 그 버전과 해시를 정확히 승인한다. 모델에는 초안 준비와 저장 기록 읽기만 제공하고 발송 도구는 제공하지 않는다. 먼저 챙겨보기와 일회성 재확인에는 초안 도구도 제공하지 않는다.

Google 읽기 계정 연결은 기존대로다. 발송을 처음 사용할 때 같은 계정으로 Gmail 읽기·기본 일정 읽기·`gmail.send`를 함께 동의한다. 설치형 OAuth는 [증분 승인을 지원하지 않으므로](https://developers.google.com/identity/protocols/oauth2/native-app) 전체 범위를 명시적으로 재연결한다. 토큰·정확한 범위·프로필·기존 연결 epoch가 모두 확인된 후에만 v2 자격 증명을 저장한다. 취소, 부분 허용, 다른 계정은 기존 읽기 연결을 대체하지 않는다. v1 읽기 자격 증명과 범위는 보존한다. 관련 메일 탐색은 이전 Google epoch에 묶여 있으므로 재연결 후 다시 선택해야 한다.

**Tada에서 메일 발송 끄기**는 로컬 발송 권한을 끄고 진행 중인 계정 요청을 중단한다. 진행 중인 발송용 Google 승인도 취소해 늦은 콜백이 권한을 되살리지 못하게 한다. 읽기 연결과 현재 계정에 유효하게 승인된 관련 메일 탐색 선택은 유지하지만 Google 계정에서 그 범위만 회수했다고 주장하지 않는다. Google 전체 연결 해제는 기존 프로젝트 토큰 회수 규칙을 따른다.

## 정확한 발송과 결과

초안은 UTF-8 일반 텍스트 최대 16 KiB, 제목 최대 500바이트, 중복 없는 받는 사람·참조·숨은 참조 합계 20명까지다. 주소는 표시 이름 없는 메일 주소로 저장한다. CR/LF 헤더 삽입, 제어 문자, 알려지지 않은 필드/버전은 거절한다. 모델 응답은 실행 인자·텍스트 16 KiB와 구독 제공자의 중복 인자·불투명 연속 상태를 포함한 전체 봉투 64 KiB를 각각 검사하며, 문맥·체크포인트 한도도 유지한다. 실제 모델이 작성할 수 있는 본문은 수신자·다른 인자의 크기에 따라 이보다 작다. 모델 답변의 출처 표기나 머리말을 메일 본문에 자동 덧붙이지 않는다. 답장은 이번 턴 `read_email`이 실제 읽은 원본의 Message-ID·References·threadId·제목만 사용한다. 원본을 읽을 권한이나 유효한 헤더가 없으면 임의로 답장 경로를 만들지 않는다. `read_email`은 완전하게 검증된 Reply-To 주소 목록과 사용 가능·헤더 없음·해석 불가 상태를 구분한다. 모델은 Reply-To를 우선하고, 헤더가 없을 때만 전체 From에서 별도로 검증한 발신 주소를 사용하며, 해석 불가 상태에서는 주소를 추측하지 않는다.

발송 전 토큰을 갱신하고, 현재 기기·계정·권한·초안 버전·내용 해시를 다시 확인한다. SQLite에 `DISPATCHING`과 시도별 Message-ID를 먼저 기록한 뒤 [messages.send](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/send)를 **한 번** 호출한다. Message-ID는 검색 상관관계이며 서버 멱등 키가 아니다. 401도 자동 재발송하지 않는다. 거절 영수증을 먼저 보존한 뒤 캐시된 인증 토큰만 갱신하며, 갱신이 불가능하면 연결 복구 상태를 표시한다. 취소/권한 해제 뒤 응답이 와도 실제 효과 영수증을 보존한다. 종료는 진행 중인 발송 처리를 기다리고, 프로세스가 죽으면 재시작 시 발송 중 기록을 `UNCERTAIN`으로 바꾼다.

- `DRAFT`: 저장된 초안. 아직 발송을 시작하지 않았다.
- `ACCEPTED`: Gmail이 접수했다. 수신·열람 증거가 아니다.
- `VERIFIED`: 전용 Message-ID로 찾은 유일한 SENT 사본의 계정·받는 사람·참조·숨은 참조·제목·본문 및 답장 연결이 일치한다. 수신·열람 증거가 아니다.
- `UNCERTAIN`: 응답 유실, 미조회, 검색 결과 없음/복수, 지원하지 않는 사본 형식. 없다는 검색 결과는 미발송 증거가 아니다.
- `REJECTED`: Gmail이 명확히 거절한 HTTP 응답. 자동 재시도하지 않는다.
- `APPLIED_MISMATCH`: SENT 사본은 있으나 승인 내용과 다르다. 효과를 보존하며 자동 재시도/보상하지 않는다.
- `DISCARDED`: 발송하지 않고 정리한 초안.

발송 직후 한 번 읽기 전용으로 확인하며, 미확정 상태에서는 사용자가 **보낸편지함에서 결과 확인**을 다시 실행할 수 있다. 조회에는 [messages.list](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list)의 정확한 Message-ID 검색과 [messages.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get)의 전체 사본이 필요하다. 임의 메일 검색 범위를 넓히거나 전체 받은편지함을 보내지 않는다. SENT 사본의 UTF-8 일반 텍스트 선언과 답장 References 계보도 대조한다. 다른 인코딩, 선언 누락이나 복잡한 MIME을 완전히 검증할 수 없으면 미확정으로 남긴다.

## 기록 업데이트와 검증 경계

v6은 기존 v1–v5 스키마 문자열을 변경하지 않고 암호화된 `mail_actions` 테이블을 추가한다. 초안·최종 답변·대화 체크포인트를 같은 트랜잭션으로 저장한다. 기존 기록은 시작 화면에서 **기록 백업하고 업데이트**를 선택해야 한다. Telegram 복원, HTTP와 서비스 타이머 시작 전에 `before-mail-*.sqlite` 백업을 만들고 파일·디렉터리를 동기화한 뒤 스키마와 해시를 함께 업데이트한다. 새 기록은 v6이다. 업데이트는 계정·대화·기기·대기 작업을 보존하며 메일 발송 권한을 켜지 않는다. 이전 실행 파일로 v6을 열 수 없다; 복귀 시 백업 시점 이후 기록이 빠진다는 점을 고려해야 한다.

로컬 테스트는 합성 Google 응답, 실제 SQLite, HTTP·대화 서비스와 브라우저를 사용한다. 실제 Gmail 발송, 실제 수신함 도착, 모델이 미지의 요청에 정확한 초안을 작성하는 품질, 물리적 휴대폰 검증 및 A12 전체 인수는 별도다. 현재 구현·로컬 검증을 출시 완료로 보지 않는다.

메일 확인창의 읽기는 응답 본문까지 15초로 제한하며, 닫기나 Escape로 즉시 중단할 수 있다. 저장·발송·확인 요청은 화면에서 30초까지만 기다린다. 이 대기 중단은 서버 작업 취소나 미발송 증거가 아니며, 발송 응답을 놓치면 재발송 버튼을 막고 최신 저장 상태를 읽도록 안내한다. 늦게 도착한 이전 응답은 다시 연 확인창을 덮어쓰지 않는다.

발송 권한을 연결하는 동안에는 메일 카드와 연결 설정에서 그 시도만 취소할 수 있다. 기존 Google 읽기 연결은 유지된다. 자동 실행으로 정상 이전할 때는 이미 접수된 메일 작업의 갱신·발송·결과 확인을 끝낸 뒤 새 호스트로 넘긴다. 명시적 종료·권한 취소는 기존 중단 경계를 유지한다.

## 대화에서 발송 결과 확인

`read_mail_action`은 저장된 `ACCEPTED`/`UNCERTAIN` 발송을 읽을 때 같은 서비스의 메일별 잠금을 통해 Gmail 보낸함을 읽기 전용으로 조회한다. 현재 대화의 취소 신호와 계정 권한을 다시 확인한 뒤에만 결과를 모델에 전달한다. 조회가 겹치거나 연결이 끊겨도 기존 영수증을 보존하며 발송 POST를 반복하지 않는다. 이미 검증된 영수증이나 미발송 초안은 저장된 관측으로 반환한다.

도구 응답의 `status_check.state`는 이번 조회 결과(`fresh`), 조회 불가(`unavailable`), 저장된 기록(`saved`)을 구분한다. `attempted`는 조회 경로가 완료됐는지 표시하며 `false`에는 다른 메일 작업이 진행 중이어서 조회를 시작하지 못한 경우도 포함한다. `VERIFIED`도 승인한 내용과 일치하는 Gmail 보낸함 사본을 뜻하며 상대방의 수신·열람을 증명하지 않는다. 모델 문맥에 전체 본문이 들어가지 않으면 `omitted_fields`와 전체 원본에 대한 해시임을 명시하고 본문만 생략한다. 생략 후에도 크기를 초과하면 읽기를 거절한다.

`mail-confirmation.test.mjs`는 실제 발송 POST의 MIME 바이트로 별도 보낸함 사본을 만든 뒤 응답을 유실시키고, 저장소와 서비스를 재시작하여 조회 가능/불가 두 조건을 검사한다. 두 조건 모두 발송 POST는 정확히 한 번이어야 한다. 이 합성 검사는 실제 계정 발송이나 모델의 자연어 판단을 대신하지 않는다.
