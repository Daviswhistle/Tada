# 같은 비서에게 어디서나 연락하기

2026-10-05 사용자 정정: **“비서가 필요한 거야. 어디서나 연락할 수 있고 사람처럼 행동하는 비서가.”** 자료 탐색과 화면 문제 해결은 비서가 쓰는 능력이지 제품 전체를 정의하는 시나리오가 아니다. 자연스러운 대화, 이어지는 관계와 업무, 연락 가능한 창구, 적절한 후속 연락을 함께 완성한다.

이 요구는 원문 §29의 모바일·원격 UI 후순위와 이전 로드맵의 특정 작업 예시 중심 개발 순서를 변경한다. 원문 파일은 보존한다. 실행 위치가 사용자 기기라는 선택과 항상 연락 가능한 비서라는 요구의 충돌은 숨기지 않는다. 최종 제품은 연락을 받는 항상 켜진 호스트와 필요한 기기에서 수행하는 작업을 분리할 수 있어야 한다. 이 구현은 호스트를 구입·배포하거나 항상 켜진 서비스를 운영하지 않는다.

## 최신 연락 호스트: 기록한 일의 일회성 직접 확인

[맡긴 일과 알림](contact-followups.md)에 이어 [일회성 로컬 재확인](contact-reviews.md)을 같은 서비스에 연결했다. 알림 시각이 있는 업무를 확정한 뒤, 소유자가 그 업무 버전의 로컬 재확인을 별도로 승인하면 약속한 시각에 허용된 자료를 한 번 확인하고 같은 대화로 답한다. 기존 모델·자료 범위·사용량·결과 저장·연락 경로를 재사용한다.

새 연락 실행 파일은 **연락 DB v4**를 요구한다. 기존 v1/v2/v3는 `--upgrade-contact`로 각 단계의 백업 후 명시적으로 전환한다. 단순 알림에는 모델이 호출되지 않는다. 파일 변경·메일/일정·외부 회신 감지·일반 컴퓨터 작업, 실제 모델/계정/휴대폰에서의 새 경로 검증은 남아 있다. 아래의 기존 기능과 역사적 검증 범위는 그대로 보존한다.

## 이번에 연결한 사용자 경험

`npm run contact`는 명시적으로 실행하는 개인 연락 호스트다. 휴대폰 크기와 PC 크기에 맞춘 같은 브라우저 화면을 제공한다. 호스트에서 발급한 일회용 링크로 각 기기를 연결하면 모두 같은 대화와 요청 상태를 본다. 작업이나 결과 파일을 먼저 골라야 하는 양식은 없다.

메시지는 처리 전에 저장된다. 브라우저 연결이 끝나도 호스트는 접수한 답변을 계속 처리하고, 다른 기기는 같은 결과를 받는다. 답변과 이어가기 문맥은 같은 트랜잭션에 저장되며 호스트 재시작 뒤 새 기기·기존 기기의 후속 질문에 복원한다. 실행 중이던 미확정 요청은 중단된 것으로 남기고 자동 재전송하지 않는다. 접수만 됐던 대기 요청은 호스트가 다시 시작할 때 처리한다.

기기별 연결을 폐기할 수 있다. 한 기기를 폐기해도 대화 전체를 지우거나 다른 기기를 로그아웃시키지 않는다. 해당 기기의 대기·실행 요청은 취소하고 뒤늦은 출력은 결과로 채택하지 않으며 이미 관측한 사용량은 보존한다. 현재의 기기 권한은 모두 같은 소유자의 대화 읽기·메시지 접수·취소 범위다. 제한된 가족/동료 공유 계정 기능은 아니다.

현재 실제 처리 능력은 기존 로컬 모델 대화와 허용한 작은 텍스트 자료 조사다. 연결된 본인 개인 채팅으로 답변을 돌려주는 연락 외에, 일반적인 외부 전송이나 파일 수정, 메일·일정, 화면 제어 또는 기존 Rust 실행기의 모든 기능이 연결됐다고 주장하지 않는다. 첫 성공은 **연락 기기가 달라도 같은 대화가 이어지고 결과를 잃지 않는 경로**이며, 업무를 능숙하게 맡는 완성된 비서의 증명은 다음 실제 업무 평가가 필요하다.

## 창을 닫아도 돌아오는 연락

후속 구현은 이 호스트와 같은 대화에 **선택적 Telegram 개인 채팅**을 연결한다. Telegram으로 맡긴 일의 답변은 그 채팅으로 전달하고, 브라우저로 맡긴 일에는 민감한 본문 없는 결과 도착 알림을 보낸다. Telegram 연결·전송은 명시적 `--telegram`과 소유자 승인 전에는 실행하지 않는다. 실제 계정·휴대폰 사용은 아직 검증하지 않았다. 설정, 데이터 전송 동의, 기존 v1 연락 DB의 백업/전환, 미확정 발송 처리는 [메시징 연락 안내](telegram-contact.md)를 따른다. Telegram은 첫 연락 창구이며 별도 비서나 제품 자체가 아니다.

## 시작하기

저장소의 고정된 Node/Rust 도구를 사용한다. 기존과 같이 본인이 관리하는 Ollama를 cloud-disabled로 실행하고 로컬 모델을 미리 설치해야 한다. 제품은 모델을 설치하거나 유료 경로로 전환하지 않는다. 초기화 시 새로운 디렉터리를 사용하고, 재시작 시 같은 디렉터리·모델·자료 범위를 사용한다.

```sh
npm ci --ignore-scripts
npm run contact -- --data ./tada-contact-private --init --model YOUR_INSTALLED_LOCAL_MODEL
```

호스트 터미널에서 16자 이상의 기록 암호를 숨김 입력한다. 암호를 두 번 확인한 뒤 일회용 연결 링크를 출력한다. 링크를 열고 기기 이름을 정하면 대화를 시작한다. `/pair`로 다른 기기용 링크를 발급하고 `/devices`, `/revoke DEVICE_ID`로 연결을 관리한다. `/quit`는 호스트를 안전하게 종료한다.

재시작은 `--init` 없이 한다. 암호를 잊으면 저장된 문맥을 복호화할 수 없다. 임의로 새 암호나 새 저장소를 자동 생성하지 않는다.

```sh
npm run contact -- --data ./tada-contact-private --model YOUR_INSTALLED_LOCAL_MODEL
```

로컬 자료 읽기를 허용하려면 기존 `tada-read-broker`를 빌드하고 `--broker ABSOLUTE_READ_BROKER --allow-read DIRECTORY`를 추가한다. 자료 범위는 최초 설정의 권한이며 매 질문의 필수 입력이 아니다. 원격 기기는 이 범위나 모델 계정을 바꾸지 못한다.

### 실제 원격 연락

기본 주소 `http://127.0.0.1:8787`은 **그 호스트 안에서만** 열린다. 이 기본값을 휴대폰 인터넷 접속으로 소개하지 않는다. 호스트 소유자가 선택한 사설 HTTPS 프록시/VPN을 사용하거나 TLS 인증서와 주소를 명시적으로 설정해야 한다. 외부 평문 리스너는 거절한다.

예를 들어 별도로 설치·인증한 Tailscale의 Serve는 사용자의 tailnet 기기들에 로컬 서비스를 HTTPS로 제공하는 경로다. [공식 Serve 문서](https://tailscale.com/docs/reference/tailscale-cli/serve)의 현재 설정·HTTPS 동의·접근 제어를 확인하고 실제 출력된 URL을 사용한다. Tada가 Tailscale을 설치하거나 계정을 만들거나 이 연결을 이번 검증에서 배포하지는 않았다. 임의의 공개 Funnel을 자동 사용하지 않는다.

```sh
# 사용자가 이미 준비한 사설 프록시에서 별도로 실행하는 예시.
tailscale serve --bg 8787
# 프록시가 출력한 정확한 HTTPS origin을 사용한다.
npm run contact -- --data ./tada-contact-private --model YOUR_INSTALLED_LOCAL_MODEL --origin https://YOUR_HOST.YOUR_TAILNET.ts.net
```

프록시는 해당 origin의 Host/Origin을 보존해야 한다. Tada는 Forwarded/X-Forwarded-User 같은 헤더를 신원이나 권한으로 신뢰하지 않는다. 직접 TLS를 쓰는 경우 `--bind ADDRESS --origin https://HOST:PORT --port PORT --tls-cert FILE --tls-key FILE`을 명시한다. TLS키·암호·기기 토큰을 저장소에 올리지 않는다. 원격 운영 전 실제 모바일 브라우저·프록시·재연결·폐기 동작을 확인해야 한다.

호스트가 자거나 꺼지면 접속과 실행도 멈춘다. 집 PC나 개인 서버 중 무엇을 계속 켜 둘지는 별도 운영 선택이다. 세션 암호를 사람이 입력하는 현재 호스트는 무인 부팅 서비스가 아니다. **항상 연락 가능함을 완성하려면 항상 켜진 호스팅·안전한 자동 기동·오프라인 접수 경로가 남아 있다.**

## 개인정보와 실행 경계

`contact.sqlite`의 대화·답변·이어가기 문맥·기기 이름은 scrypt로 유도한 키와 AES-256-GCM으로 암호화한다. 새 nonce와 목적별 AAD를 사용하며, 설치 ID·모델/자료 범위의 fingerprint가 다른 저장소를 같은 이어가기 문맥으로 채택하지 않는다. 장기 시스템 지시를 저장해 다시 권한으로 주입하지 않고 현재 호스트 지시를 새로 만든다. 소스의 원문은 여전히 untrusted tool data다.

기기 비밀은 DB에 해시만 저장한다. 연결 링크는 256-bit 일회용 코드, 5분 수명이며 페이지가 열리면 fragment를 주소창에서 제거한다. HTTPS 쿠키에는 Secure, HttpOnly, SameSite=Strict, Path=/를 적용한다. 기본 30일 수명과 호스트 폐기가 있으며, 원격 화면에 호스트키·원문 tool context·이어가기 checkpoint API를 노출하지 않는다. 쿠키는 대화 접근권이므로 기기 잠금과 브라우저 보안도 필요하다.

SQLite WAL/FULL과 별도 프로세스 수명 잠금으로 하나의 호스트만 쓰게 한다. 접수·사용량·답변/checkpoint commit은 트랜잭션으로 처리한다. 저장 오류는 새 실행을 차단한다. 프로세스 강제 종료 뒤 잠금이 해제되는 것과 기존 요청이 복원되는 것을 회귀 검사한다.

이 저장소는 기존 Rust 외부 행동 ledger를 대체하지 않는다. 소유한 로컬 파일시스템을 신뢰하며 동일 OS 사용자나 관리자에 대한 완전한 격리, Windows ACL의 별도 교정, 디스크 물리적 고장, DB 전체와 키 자료의 동시 롤백 감지는 이번 보장이 아니다. 암호화하지 않은 상태·사용량·기기 만료 메타데이터는 남고 원문 자료는 복호화된 메모리에 존재한다. JavaScript 변수 참조 제거를 완전한 메모리 소거라고 주장하지 않는다.

현재 모의 경계에서 도출된 실행 한도인 journal당 모델 요청 64회, 모델 문맥 14 KiB를 그대로 유지한다. `/forget`이나 재시작으로 한도를 몰래 초기화하지 않는다. 16개 대기 요청, 1,000개 대화 turn, 기기 8개, 페이지당 50개를 제한하며 이전 기록은 페이징한다. 이 한도는 평생 비서의 충분한 기억이 아니다. 명시적인 예산 갱신·문맥 압축/검색과 사용자가 기억을 검토·삭제하는 경로가 후속 작업이다.

## 연락과 알림의 현재 의미

열려 있는 연결에서는 새 답변이 자동으로 표시된다. 사용자가 허용하면 지원되는 브라우저에서 페이지가 열려 있는 동안 민감 본문 없이 “새 답변” 알림을 시도한다. 결과는 알림 수신 여부와 무관하게 대화에 남는다.

**선택적 Telegram 개인 채팅과 결과 전송 코드는 연결됐다.** 실제 Telegram 계정의 발송·휴대폰 알림 검증은 아직 없고, 서비스워커 Web Push, 문자·전화, 음성 대화, 다른 사람의 회신을 기다렸다 이어 하는 장기 약속 처리도 남아 있다. 이벤트 스트림을 서비스워커 푸시와 혼동하지 않는다. [Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)에서 페이지 수명과 persistent notification 경로가 구분됨을 따른다. 이번 코드가 임의의 장기 감시나 외부 연락을 등록하지 않는다.

## 검증과 다음 완성 조건

`contact.test.mjs`는 실제 SQLite/HTTP와 합성 모델로 기기 간 대화, 재시작·중복 접수·취소·기기 폐기·암호화·호스트 잠금·실제 프로세스 종료·원문 권한 주입 거절을 검사한다. 단위시험이 모델의 대화 능력을 증명하지 않는다. `contact-model-smoke.mjs`는 실제 선택한 로컬 모델을 사용해 첫 기기의 대화를 다른 기기에서 읽고 호스트를 재시작한 뒤 후속 질문을 처리한다. 실제 실행 여부와 결과는 실행한 환경과 정확한 코드 버전별로 남긴다. 현재 연락 패키지는 GitHub에 반영되지 않았으므로 이 코드가 PR CI에서 통과했다고 표시하지 않는다. 전체 assistant-v1 16건은 이 시험으로 합격 처리하지 않는다.

다음 사용자 경험은 이 **하나의 대화**에서 장기 업무를 맡기고, 사용자가 앱을 떠난 동안 완료/결정 필요를 실제 연락 채널로 받으며, 돌아와 수정하거나 다른 일을 이어 맡기는 것이다. 화면 문제나 조사 예문을 다시 독립 제품으로 키우지 않는다. 대화 기억, 현재 업무, 관련 도구·개인 계정은 목적을 위한 수단이다.

공식 구현 참고: [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [Node crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html), [Secure cookies](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Set-Cookie). API 설명은 Tada의 독립 보안 감사를 대신하지 않는다.
