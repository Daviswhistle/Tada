# 같은 비서에게 맡긴 일을 약속한 시각에 한 번 확인시키기

2026-10-07 · 연락 DB v4. 기존 연락/업무/알림 구현에 추가하는 실행 가능한 코드다. 배포된 상시 서비스나 실제 모델의 업무 성공을 뜻하지 않는다.

## 바뀐 사용 흐름

이전에는 확인 시각이 되면 저장한 문구로 알렸다. 이제 소유자가 **특정 업무 버전의 재확인**을 별도로 승인하면, 같은 호스트가 그 시각에 같은 로컬 모델과 허용된 자료를 사용해 한 번 확인하고 결과를 기존 대화에 저장한다. 별도 봇·대화·사용 한도를 만들지 않는다.

예를 들어 “보고서 비용을 내일 다시 확인할 일로 기억해줘”라고 말하고 제안의 내용·시각을 **이대로 맡기기**로 확정한다. 저장된 업무 카드의 **이 시각에 직접 확인하고 알려줘**를 누르면 실제 제목·내용·날짜/시간대, 로컬 자료 읽기 범위, 최대 호출 수와 취소 경계를 보여 준다. 그 확인을 수락해야 자동 재확인이 예약된다. 창을 닫아도 호스트가 켜져 있으면 실행하며, 다른 연결 기기에서 같은 기록과 결과를 본다.

현재는 업무 저장과 재확인 승인에 **두 번의 확인**이 필요하다. 문장을 입력했다는 이유만으로 미래의 추론 실행을 승인하지 않는다. 모델은 업무를 제안할 수 있지만 재확인 승인 API를 도구로 받지 않는다. 날짜 없는 일이나 완료/취소된 일은 재확인을 예약할 수 없다. 권한 있는 관련 자료를 발견하지 못하면 그 한계를 설명하는 답변이어야 하며, 제품이 현재 실질적 답변 품질까지 검증된 것은 아니다.

## Telegram에서도 같은 비서와 같은 승인

연결된 본인 채팅에서 `/confirm PROPOSAL_ID`로 업무를 확정하면, 확인 메시지가 해당 업무의 정확한 식별자·버전과 별도 실행 범위를 안내한다. `/review COMMITMENT_ID VERSION`으로 그 버전의 재확인을 승인하고, `/review-cancel COMMITMENT_ID VERSION`으로 취소한다. 정상적인 자연어 업무 대화에는 식별자를 직접 만들 필요가 없지만, 이 미리보기의 Telegram 승인 명령에는 표시된 식별자가 필요하다.

기존에 승인한 본인 Telegram 연결만 사용한다. 외부인이 보낸 메시지, 전달된 메시지, 단체 채팅과 봇이 대신 보낸 메시지는 승인이 아니다. Telegram에서 승인한 재확인의 답변은 그 채팅으로 전달한다. 브라우저에서 승인한 재확인은 브라우저 기록에 답변을 남기고, Telegram에는 본문 없는 결과 알림만 전한다. 추가 제3자 수신자를 허용하지 않는다. 연결 전 동의한 같은 대화의 문맥이 답변에 반영될 수 있다.

## 실행 범위와 한도

허용하는 도구는 기존 로컬 읽기 경로의 `list_sources`, `list_files`, `read_file`뿐이다. 향후 호스트에 쓰기 도구를 추가해도 이 승인에 자동 포함되지 않는다. 새 메일/일정 권한, 웹 조사, 파일 수정, 프로그램 실행, 외부 사람에게 발송, 반복 감시는 제공하지 않는다.

한 번의 재확인은 모델 요청 최대 **8회**이며, 기존 **기록당 64회** 한도에서 함께 차감한다. 문맥 **14 KiB**, 전체 대기 요청 16개, 대화 1,000건, 기기 8개와 30일 접근 수명도 유지한다. 예약 대기 중인 재확인은 최대 32개, 재확인 기록은 최대 1,000개다. 한도 초과는 실패 상태로 남기며 재시작이나 새 예약으로 한도를 초기화하지 않는다. 이 한도 때문에 현재 구현은 장기간 무제한 비서로 사용하기에 부족하다. 모델 응답 품질과 장기 문맥 관리는 별도 제품 과제다.

실행은 같은 `ConversationAssistant`와 자료 게이트웨이를 거친다. 예약한 업무가 실제 사람이 방금 말한 것처럼 위장되지 않도록 표시하고, 읽은 원문을 지시가 아니라 자료로 취급한다. 모델에 현재 관측과 다음 행동을 요구하며, 실제 사용한 인용 자료는 기존 검증 경로로 다시 읽는다. 이 재확인은 근거 일치 확인이지 답변 의미 전체에 대한 독립 검증이 아니다. 답변 생성 후에도 업무 상태를 자동으로 완료 처리하지 않는다.

## 변경·취소·중단

승인은 업무 식별자, 버전, 승인 기기, 정확한 시각·내용에 묶인다. 업무를 수정하면 기존 예약이 취소되고 새 버전에는 새 승인이 필요하다. 같은 승인 요청이나 시각 처리의 재전송은 새 실행을 만들지 않는다. 완료되거나 취소된 같은 버전은 다시 승인해도 재실행되지 않는다. 새로운 확인이 필요하면 대화로 새 업무 버전·시각을 만든다.

업무를 저장한 기기와 재확인을 승인한 기기의 접근권을 확인한다. 어느 쪽이든 폐기·만료되면 새 실행과 뒤늦은 결과를 막는다. 모델 요청 직전, 자료 관측 전후, 최종 결과 저장, 전송 대기열에서 최신 버전을 다시 확인한다. 취소 직전에 모델이 사용한 자원은 취소할 수 없으므로 관측된 사용량은 보존한다. 이미 전송했거나 발송 여부가 미확정인 메시지를 “없었던 것”으로 되돌리지 않는다.

호스트가 늦게 켜졌거나 대기열에서 오래 지연돼 예정 시각보다 **24시간을 초과해 시작하지 못한 일**은 `CONTACT_REVIEW_MISSED`로 취소한다. 실행 중 호스트가 중단되면 `interrupted`로 남기고 자동 재시도하지 않는다. 예약당 최대 한 번 접수하지만 중단·권한·용량에 따라 실행 자체가 없을 수 있다. 성공을 보장하는 “정확히 한 번 실행” 주장이 아니다.

Telegram의 명확한 429 거절 후 재시도하더라도 새 취소·업무 버전을 검사한다. 발송이 불확실한 경우 자동 재전송하지 않는다. 답변이 이미 저장된 뒤 전송을 취소하면 저장된 결과는 그대로 남고 아직 대기 중인 전달만 억제한다.

## 실행과 기존 기록 전환

전체 저장소의 고정된 Node 런타임과 잠긴 의존성을 사용한다. 이미 설치된 본인 로컬 모델 식별자를 사용하며, 암호·봇 토큰을 명령행이나 저장소에 넣지 않는다.

```sh
npm ci --ignore-scripts
npm run contact -- --help
# 새 기록 디렉터리일 때만 --init
npm run contact -- --data ./tada-contact-private --init --model YOUR_INSTALLED_LOCAL_MODEL --timezone Asia/Seoul
# 기존 v1/v2/v3 기록: 백업 후 명시적 전환
npm run contact -- --data ./tada-contact-private --model YOUR_INSTALLED_LOCAL_MODEL --timezone Asia/Seoul --upgrade-contact
# 이후 재시작
npm run contact -- --data ./tada-contact-private --model YOUR_INSTALLED_LOCAL_MODEL --timezone Asia/Seoul
```

자료를 읽으려면 기존 `tada-read-broker`와 최초 허용한 `--broker ABSOLUTE_READ_BROKER --allow-read DIRECTORY` 설정을 함께 사용한다. 동일 기록의 모델/자료 범위 지문을 임의로 바꾸지 않는다. 본인 Telegram 연결도 사용할 때만 기존 `--telegram` 옵션을 추가한다. 모델·토큰·VPN·서버를 자동으로 설치하거나 구입하지 않는다.

기존 v1→v2→v3→v4는 각 단계 전에 일관된 새 SQLite 백업을 생성·동기화한다. v4는 v3 위에 `followup_reviews` 테이블과 시각 인덱스를 추가하며 v1–v3의 스키마 원문은 바꾸지 않는다. 정상 재시작으로 몰래 전환하지 않는다. 이 연락 DB 버전은 Rust의 다른 작업 DB 버전과 별개다.

승인 스냅샷은 기존 키로 암호화하고 업무 버전/기기/시각을 인증한다. 접수된 실행의 식별자·기기·텍스트가 승인에 연결된 값과 일치해야 한다. 같은 OS 사용자/관리자, 전체 DB 롤백, 디스크 손상에 대한 완전한 방어 또는 독립 보안 심사로 표현하지 않는다.

## 실행한 검증과 남은 검증

로컬 Node 22.16.0에서 실제 SQLite, HTTP, 자식 프로세스, 실제 호스트 타이머를 사용하는 기존 및 신규 회귀 검사를 실행했다. 모델 답변과 Telegram은 합성 프로토콜 시험이다. 새 시험에는 실제 임시 파일의 변경/재읽기, 업무 버전 변경, 권한 폐기, 중단 뒤 미확정 사용량, 한도 공유, 암호화 메타데이터와 실행 연결 변경 검출이 포함된다. 제품 코드에 시험용 도구나 운영용 우회 엔드포인트를 추가하지 않았다.

새 브라우저 시험 `evals/assistant-v1/contact-review-browser-smoke.mjs`도 작성했다. 이 환경의 Chromium은 실행됐지만 첫 페이지 이동에서 **`net::ERR_BLOCKED_BY_ADMINISTRATOR`**를 반환했다. 따라서 실제 승인 UI, 화면 크기별 배치, 기기별 화면 동기화 시험은 이 변경분에서 통과했다고 주장하지 않는다. 브라우저 정책을 우회하지 않았다. 접근이 허용된 개발 환경에서 다음 명령으로 확인해야 한다.

```sh
node --experimental-strip-types --test packages/engine/tests/contact.test.mjs packages/engine/tests/followups.test.mjs packages/engine/tests/telegram-contact.test.mjs packages/engine/tests/reviews.test.mjs
node --experimental-strip-types evals/assistant-v1/contact-review-browser-smoke.mjs
```

이번 환경은 변경 소스 부분 체크아웃이며 전체 저장소 CI를 수행하지 않았다. 전체 Node/Rust 검사, Windows, 실제 로컬 모델, 실제 Telegram 계정과 휴대폰, 원격 배포, 비서 제품 시나리오 16건은 새 경로의 검증으로 남아 있다. 이전 PR의 성공을 이번 변경의 성공으로 대체하지 않는다.
