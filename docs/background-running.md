# 같은 비서의 자동 실행과 복구

설정 → 먼저 챙기기의 **자동 실행 켜기**는 현재 계정·모델·자료 범위와 대화를 그대로 사용하는 사용자 서비스 설정이다. 별도 비밀번호나 다른 계정, 공개 포트를 만들지 않는다. 동의 값은 `same_assistant_background_v1`이며 인증된 브라우저에서 선택한다.

[Windows 설치본](windows-portable.md)은 같은 설정에서 현재 사용자 로그인 시 실행할 고정 진입 파일을 등록한다. 일반 브라우저의 수명에 관여하는 작업 스케줄러 작업은 만들지 않는다. Windows 시작 앱 설정의 차단 여부와 실제 다음 로그인 실행은 등록 상태만으로 확인할 수 없다. Windows 설치본의 트레이에서 같은 대화를 다시 열거나 **작업을 멈추고 종료**할 수 있다. 명시 종료는 새 접수·자동 확인을 막고 실행 중 작업을 중단하며, 기록과 대기 요청은 보존한다. 재시작 제한과 상세 종료 동작은 위 문서를 따른다.

아래의 서비스 이전과 unit 설명은 Linux의 사용자 systemd가 있는 환경에 해당한다. 이 프로젝트의 자동 키 보호는 Windows/WSL에 있으므로, 실제 기본 경로의 조합은 WSL + 사용자 systemd다. WSL 환경이 시작돼 있어야 하며 Windows 부팅·로그인 자체를 자동화하지 않는다. 절전·전원 종료 중 연락과 물리적 휴대폰 수신을 보장하지 않는다. 지원 플랫폼 전체의 설치 패키지나 출시 검증을 대신하지 않는다.

켜면 현재 데이터 위치에 결합된 한 서비스만 설치하고 실행한다. 접수한 대화는 끝까지 처리하고, 새 접수를 닫은 뒤 기존 실행이 소유권을 반환한다. 서비스는 그 소유권을 기다렸다가 같은 기록을 연다. 브라우저는 같은 주소로 다시 연결하며 작성 중인 내용은 새로고침하지 않는다. `npm start`는 실행 중인 서비스의 시작 화면을 다시 연다. 동시에 두 개의 비서를 시작하지 않는다.

**다음 자동 시작 끄기**는 다음 환경 시작 시의 자동 실행만 해제한다. 현재 실행 중인 비서·복구 기능과 계정·기록을 삭제하거나 중지하지 않는다. 실행 중 서비스를 중지하면 다음 시작은 기존 `npm start`로 할 수 있다.

서비스는 절대 Node·앱 경로와 기존의 비밀 없는 실행 설정만 보관한다. 초기화·로그인·기록 업데이트 플래그는 반복 실행에서 제외한다. unit은 개인 파일로 생성하고, 다른 내용의 기존 unit이나 심볼릭 링크는 덮어쓰지 않는다. 토큰·보호 키·setup/pair URL을 unit과 환경변수에 넣지 않으며 서비스 stdout을 보관하지 않는다. 현재 체크아웃·Node 설치 위치를 옮기면 실행 설정을 다시 준비해야 한다.

프로세스의 비정상 종료는 systemd가 10초 뒤 재시작하며 5분 동안 5회로 제한한다. 시작 중 일시적인 연결 실패는 5초·30초·2분·5분·이후 15분 간격으로 다시 확인한다. 진행 중 대화와 불명확한 발신은 다시 실행하지 않는다. 로그인·불확실한 토큰 갱신·보호 키·저장소·기록 업데이트 문제는 자동으로 진행하지 않으며 `npm start`의 복구 화면에서 알린다. 재시작은 이미 접수한 요청의 `interrupted`·`unknown` 기록을 보존한다.

검증은 설치 동의와 권한 재검사, 정확한 옵션과 unit 인자, 기존 unit 보존, 요청을 완료한 뒤 단일 소유권 이전, 초기화 없는 재시작, 일시적 오류 복구·로그인 비재시도·종료 시 재시도 취소를 포함한다. 실제 사용자 서비스의 계정 복원과 종료 후 복구는 별도 운영 증거로 확인한다.

고급 실행의 Google 환경변수 설정이 암호화해 저장된 설정과 다르면 자동 실행 이전을 거부하고 현재 대화를 유지한다. 빈 환경변수로 연결을 끈 경우도 포함한다. 사용자 서비스는 상속받은 Google 클라이언트 환경변수를 제거하고 저장된 동일 설정만 사용한다. 자동 실행 상태 조회는 비동기로 캐시하며 서비스 관리자 응답이 느려도 대화 조회를 지연시키지 않는다.
