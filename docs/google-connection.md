**2026-10-10 추가:** 기본 Gmail·일정 연결은 읽기 전용으로 유지합니다. [메일 초안과 발송](mail-actions.md)을 사용하려면 v6 기록과 별도의 명시적 발송 연결이 필요합니다. 아래의 발송 제외 설명은 기본 읽기 도구의 범위이며, 새 발송 경로와 구분합니다.

# Gmail과 Google Calendar 연결

Tada 설정에서 Google 계정을 연결하면 **같은 연락 대화**가 Gmail과 기본 캘린더를 읽을 수 있다. Google에서 승인하는 범위는 `gmail.readonly`와 `calendar.events.readonly`뿐이다. 메일 발송·라벨 변경, 일정 생성·수정·삭제, 첨부 다운로드, 링크 방문은 지원하지 않는다.

## 기본 읽기 범위와 모델 전송

아래는 기본 연결의 범위다. 받은편지함 밖의 관련 메일 탐색은 [추가 설정](#관련-메일-탐색과-발신-기록)을 별도로 켰을 때만 가능하다.

- 받은편지함의 최근 7일에서 최대 20개 메시지의 보낸 사람, 제목, 날짜와 짧은 미리보기를 읽는다. 관련 메시지가 있으면 그 목록에 나온 메일 하나의 텍스트 본문을 UTF-8 기준 최대 4 KiB까지 읽을 수 있다. [MIME alternative](https://www.rfc-editor.org/rfc/rfc2046.html) 안에서 일반 텍스트를 우선하고, mixed의 독립적인 본문과 푸터는 순서대로 보존한다. HTML은 화면에 표시하거나 링크·첨부를 실행하지 않고 글자로만 정리한다. 파일명 또는 `Content-Disposition: attachment`가 있는 파트와 그 하위 파트는 제외하며, 파일명이 없거나 중복 헤더에 inline도 있어도 첨부를 읽지 않는다. 보낸편지함과 전체 스레드는 읽지 않으므로 받은편지함에 남아 있거나 읽지 않은 메일이라고 해서 답장하지 않았다고 판단할 수 없다. 도구 응답과 모델 안내에도 답장 여부를 확인할 수 없음을 명시한다.
- 제목·발신자 이름의 [RFC 2047](https://www.rfc-editor.org/rfc/rfc2047.html) B/Q 인코딩과 인접 encoded-word를 해석한 뒤 표시와 UTF-8 길이 제한을 적용한다. 해석할 수 없는 헤더는 해당 필드만 비우고 `unavailable_headers`로 표시한다. 본문은 MIME 파트의 문자셋으로 해석하며 UTF-8, EUC-KR, ISO-8859-1 등 지원하는 문자셋을 UTF-8 텍스트로 변환한다. 지원하지 않거나 잘못된 인코딩을 UTF-8로 추측해 읽지 않는다.
- [Gmail의 별도 저장 본문](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages.attachments#MessagePartBody)은 첨부 조회 경로를 추가하지 않고 읽기 불가로 처리한다. 읽을 수 있는 텍스트가 전혀 없으면 명시적인 도구 오류를 반환한다. 일부만 읽으면 `body_status: partial`, `omitted_body_parts`와 `truncated`를 원문 근거에도 함께 기록한다. 빈 일반 텍스트 alternative가 있으면 읽을 수 있는 HTML 텍스트를 사용한다. 읽기 불가와 실제로 빈 inline 본문을 구분하며, 빠진 내용을 빈 메일이나 완독한 본문으로 주장하지 않는다.
- HTML 정리는 입력을 한 번씩 소비하며 태그의 따옴표, 줄바꿈과 글자 참조를 처리한다. 주석과 script·style·noscript·svg·iframe·object 내용은 제외한다. 닫히지 않은 태그·주석·제외 영역 등 잘못된 HTML은 `malformed_text`로 알리며, 다른 읽을 수 있는 본문이 없으면 읽기 불가 오류를 반환한다. 본문 조회와 출처 재검증 모두 같은 제한을 적용한다.
- 기본 Google Calendar에서 현재 시각부터 다음 7일의 일정 최대 20개를 읽는다. 종일 일정도 포함하며, 더 있으면 답변 근거가 잘릴 수 있다. [Google 이벤트의 종료 의미](https://developers.google.com/workspace/calendar/api/v3/reference/events)에 따라 `endTimeUnspecified: true`이면 제공된 종료 값은 호환용이며 실제 종료·지속 시간이나 이후 여유 시간을 추정하지 않는다. 이 표시도 출처 해시와 재검증에 포함한다. 생략된 표시는 문서상 기본값 false로 해석하고 잘못된 타입은 거절한다. 확정된 종료 값은 해당 시각·날짜를 포함하지 않으며, 종일 일정의 종료 날짜도 마지막 날 다음 날이다.
- 명시적인 IANA `timeZone`이 있으면 오프셋 없는 일정 `dateTime`도 해당 시간대의 현지 시각으로 보존한다. 날짜·시·분·초와 시간대를 검증하며, 호스트 시간대나 UTC·DST 시각으로 추측 변환하지 않는다. 명시된 시간대는 오프셋이 있는 시각·종일 날짜에서도 출처 해시에 포함하므로 시간대만 달라져도 재검증이 실패한다. 잘못된 비취소 일정은 누락 수 `omitted_events`와 `truncated: true`로 알리며 완전한 빈 목록으로 주장하지 않는다.
- 질문 답변에 필요한 관측 내용은 사용자가 선택한 Tada 모델로 전송된다. 이메일·일정 내용은 외부 작성자가 제공한 데이터로 취급한다. 그 안에 들어 있는 지시가 Tada의 권한이나 사용자 의도를 바꾸지 않는다.
- Google 근거는 현재 턴에서 읽고 발급한 출처만 인용할 수 있다. 과거 대화의 출처만으로 옛 날짜 범위나 메일 본문을 다시 조회하지 않는다. 이번 턴의 목록과 metadata 응답에서 받은편지함 소속 및 최근 7일 범위를 확인하고, full 응답에서도 다시 검사한 뒤 본문을 전달한다. 그 사이 보관되어 범위를 벗어난 메시지의 제목·미리보기·본문은 모델에 전달하지 않는다. 답변을 채택하기 전에는 같은 계정과 현재 권한으로 근거를 다시 읽고 해시를 비교한다.
- 작은 문맥의 공급자는 목록 응답을 모델 메시지 직렬화 기준 각각 최대 2,048바이트, 한 턴의 Google 도구 메시지를 합계 최대 6,000바이트로 제한한다. 공급자 문맥이 32 KiB 이상이면 목록 최대 24 KiB·합계 48 KiB를 상한으로 사용하되 실제 남은 모델 문맥에 맞춰 더 줄인다. 이 자료 한도와 별도로 실제 모델 요청의 도구 스키마, 누적 대화, 출처 ID와 같은 배치의 도구 응답을 함께 계산한다. 남은 호출이 실패해도 그 실제 오류 응답 상한까지 문맥에 들어가도록 예약한다. 구독 경로는 `ChatGPTSubscription.contextBytes`의 실제 요청 직렬화를 사용하며, 공급자의 요청 한도에 맞춰 목록의 뒤쪽 항목이나 본문을 더 줄인다. 기본·로컬 경로는 14,000바이트, ChatGPT 구독은 암호화된 연속성 정보까지 포함한 전체 요청 64 KiB로 제한한다. 본문 한 메일당 4 KiB 한도는 큰 문맥에서도 그대로다. 줄였으면 `truncated`로 알리고 본문 발췌의 바이트 상한은 출처 식별 정보에도 보존해 이번 턴의 검증에서 같은 발췌를 재현한다.
- 같은 배치의 로컬 파일도 남은 실제 문맥에 맞게 UTF-8 발췌로 줄일 수 있다. 네이티브 broker의 전체 파일 8 KiB 한도는 그대로이며, 발췌의 `truncated`·`excerpt_bytes`와 원본의 경로·전체 바이트 수·SHA-256을 함께 반환한다. 답변 검증은 원본 전체 파일을 다시 해시하므로 보이지 않은 뒤쪽의 변경도 거절한다. 예산을 지키지 않는 다른 도구 응답은 출처 발급 전에 제한 오류로 처리해 본문이 다음 모델 요청에 들어가지 않게 한다. 문서 준비와 맡긴 일 제안도 응답 예산을 확인한 뒤에만 저장 후보를 만들며, 거절된 호출의 문서나 카드는 최종 답변과 함께 저장되지 않는다. 저장 문서는 실제 compact 도구 메시지 표현으로 예산을 계산한다.
- 먼저 챙겨보기의 파일 근거는 이번 검사에서 실제로 읽은 저장 문서의 출처만 확인한다. 옛 대화의 파일 인용을 새 파일 읽기 권한으로 사용하지 않는다. 저장 문서와 현재 Google 자료를 함께 인용한 답변은 저장 근거 검사로 보수적으로 표시하며, 문서의 외부 원본까지 새로 확인했다고 주장하지 않는다.

설정의 연결 버튼 앞에는 선택한 모델로의 전송과 먼저 챙겨보기의 별도 동의를 두 문장으로 설명한다. 자세한 조회 범위와 답장 여부·잘림의 제약은 접어서 열 수 있는 “확인하는 자료와 범위”에 둔다. 첫 인증 대기 중에는 “연결 취소”로 즉시 취소하고 재시도할 수 있다. 기존 계정을 다시 연결하는 중에는 “연결 취소 및 Google 연결 해제”가 기존 자격 증명도 지움을 알린다. 로그인이 끝나면 Google 계정 주소와 최근 확인 시각을 표시한다. 연결을 해제하면 로컬 자격 증명을 먼저 지우고 진행 중인 인증·읽기·답변을 중단한다. Google 서버에서 권한이 취소됐는지는 별도로 확인해 알려 준다. 첫 인증 취소 안내는 자격 증명을 지웠다고 주장하지 않는다. 과거 대화와 저장 답변은 남는다. Google 연결을 소유한 기기의 권한이 취소되면 해당 연결을 중단하지만, 연결을 소유하지 않은 다른 기기의 취소는 진행 중인 사용자 답변을 중단하지 않는다.

연결 해제의 권한 변경은 로컬 자격 증명을 지우는 즉시 알린다. 자격 증명이 없는 첫 인증이나 대기 중 인증만 취소하면 Google 권한 변경으로 처리하지 않으며 진행 중인 일반 대화는 계속한다. Google의 늦은 revoke 응답은 해제 결과만 갱신하며 이후 시작한 대화를 중단하지 않는다. [Google의 토큰 회수](https://developers.google.com/identity/protocols/oauth2/native-app#tokenrevoke)는 같은 프로젝트의 승인과 발급된 토큰 전체에 적용되므로, 새 연결은 진행 중인 회수 요청이 끝난 뒤 callback 리스너와 인증 화면을 연다. 이 대기 중에도 연결을 취소할 수 있으며 취소된 시도는 회수가 끝나도 다시 열리지 않는다. 회수 요청은 기존 3초 한도로 끝내고 자동 재시도하지 않는다. 시간 초과 등으로 원격 회수를 확인하지 못하면 그 불확실성을 유지한 채 대기를 해제하며, Google 서버의 실제 권한 제거를 보장하지 않는다. 옛 해제 결과가 새 인증 오류를 덮지 않는다. 토큰 갱신에서 승인 범위가 축소되면 현재 연결에 권한 거절과 재연결 필요 상태를 저장하고, 다시 연결하기 전에는 추가 Google 읽기와 먼저 챙겨보기의 Google 조회를 막는다. 이 상태는 저널을 다시 열어도 유지된다.

Google 스냅샷을 사용하는 일반 대화와 먼저 챙겨보기는 권한이 바뀌면 중단한다. Google 도구와 스냅샷이 없는 예약된 일회성 로컬 자료 확인은 Google 해제·첫 연결·재연결과 독립적으로 계속한다. 해당 확인의 업무 버전·기기·로컬 자료 권한 검사와 실제 파일 해시 재검증은 그대로 적용하며, 무관한 Google 변경 때문에 일회성 검토를 잃거나 재실행하지 않는다.

토큰 갱신·API의 시간 초과와 잘못되거나 너무 큰 원격 응답은 현재 연결의 일시적 오류로 표시한다. 응답 형식·크기 오류의 원래 진단과 이전 성공 확인 시각은 보존한다. 토큰·프로필·Gmail·Calendar 응답은 최상위 JSON 객체여야 하며, 배열·문자열·숫자·불리언·null을 빈 목록 근거로 인정하지 않는다. 메일·일정 목록의 유효한 빈 객체나 객체 안의 빈 목록은 실제 빈 결과로 읽고 재검증할 수 있다. 프로필의 HTTP 403은 본문 형식과 무관하게 읽기 권한 거절로 안내한다. 실패한 재연결은 이전 계정의 자격 증명과 확인된 승인 범위를 유지한다. 사용자 취소나 연결 epoch 변경은 권한 취소로 처리하며, 늦은 실패가 새 연결에 오류를 기록하지 않는다. 시간 초과를 자동으로 재시도하지 않고 다음 명시적 조회의 성공으로 일시적 오류를 해제한다.

로컬 자격 증명 삭제와 토큰 없는 회수 기록의 저장은 기존 v5 설정에서 같은 암호화 트랜잭션으로 처리한다. 회수 기록에는 버전, 이전 연결 epoch와 원격 확인 여부만 둔다. 회수 중 중단되거나 확인하지 못한 결과도 재시작 뒤 미확인으로 남으며, 토큰을 보관해 다시 회수하지 않는다. 완료 응답은 현재 회수 기록의 epoch가 일치하고 새 자격 증명이 없을 때만 갱신한다. 새 Google 연결이 성공하면 자격 증명 저장과 이전 회수 기록 정리를 함께 처리한다. 기존 저널 스키마와 기록을 자동 이전하지 않는다.

대화의 Google 조회 실패 카드에도 사람이 이해할 수 있는 오류 안내를 표시한다. 재연결·읽기 권한 문제가 있으면 “Google 연결 설정” 버튼으로 설정을 열어 연결 상태를 확인할 수 있으며, 버튼은 인증이나 요청을 자동 실행하지 않고 작성 중인 메시지를 보존한다. 같은 실패를 Telegram에서 받으면 컴퓨터의 Tada 설정에서 Google 연결을 복구하도록 안내한다. 일시적 오류와 잘못된 응답은 잠시 후 새 메시지로 요청하도록 알리고, 크기 제한은 요청 내용을 좁히거나 다른 자료로 진행하도록 구분한다. 알려지지 않은 오류의 내부 코드는 표시하지 않는다.

## 관련 메일 탐색과 발신 기록

Google 연결 아래의 **관련 메일까지 찾아보기**를 별도로 켜면, 같은 계정의 받은·보낸·보관 메일에서 필요한 주제나 사람을 검색할 수 있다. 기존 연결과 기존 기록은 자동으로 이 범위를 얻지 않는다. 설정은 v5 암호화 설정에 버전·Google 연결·동의한 기기와 함께 저장하며, Google 재연결이나 동의 기기 만료 후에는 다시 선택해야 한다. 끄거나 다시 켜면 이전 실행의 권한을 재사용하지 않는다.

`search_related_emails`는 1–5개의 제한된 일반 검색어로 호스트가 [Gmail 검색](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list)을 구성한다. 모델이 URL이나 Gmail 연산자로 범위를 바꿀 수 없다. 과거의 관련 자료도 찾을 수 있도록 검색에 7일 제한은 두지 않으며 스팸·휴지통·임시보관은 제외한다. 결과는 페이지당 최대 20개, 대화 한 차례에서 최대 세 페이지다. 다음 페이지는 이번 실행에서 발급한 커서와 같은 검색어로만 읽는다. 미리보기가 문맥 한도로 더 줄면 `truncated`를 표시하고 화면에 제공한 ID만 선택할 수 있다.

`read_email_thread`는 이번 대화에서 찾은 메일을 기준으로 [같은 대화의 메타데이터](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.threads/get)를 조회하고, 최근 20개의 보낸 사람·제목·시각·미리보기·SENT 라벨 여부를 제공한다. 최신 항목부터 문맥에 맞추며, 제외하거나 생략한 항목이 있으면 일부 관측임을 표시한다. 더 자세한 내용은 공개된 메일 ID의 본문 최대 4 KiB로 읽는다. 첨부·스팸·휴지통·임시보관 본문은 읽지 않는다. 큰 원격 대화 응답은 256 KiB에서 거절하므로 모든 크기의 대화를 완독한다고 보장하지 않는다.

**나중에 보낸 메일이 관측됐다는 사실은 모든 요청을 해결했다는 증명이 아니다.** 다른 경로의 회신이나 외부 업무 완료를 추정하지 않는다. 새 수신 메일이 앞선 답장 이후에 온 경우에도 이전 발신 기록만으로 답변 완료라고 하지 않는다. 검색·대화·본문의 인용은 답변 직전에 현재 자료와 다시 대조한다. 원문은 해당 모델 호출에서만 사용하며, 다음 대화의 체크포인트에는 Google 원문 대신 재조회 안내만 남긴다. 답변과 출처 영수증은 기존 암호화 기록에 보존된다.

먼저 챙겨보기가 별도로 켜진 경우에는 이 추가 범위도 활용할 수 있다. 수시 확인은 최근 7일 보낸 메일 최대 20개의 ID 변화도 관측해, 받은편지함이 같아도 발신 이후 상황을 다시 판단할 수 있게 한다. 발신 변화만으로 재알림이나 업무 완료를 자동 확정하지 않는다. 기존 모델 사용량·하루 네 번·시간 간격은 그대로이며 설정을 껐다 켜도 초기화하지 않는다. 권한 변경은 진행 중인 읽기·늦은 답변·대기 중인 이전 자동 제안을 무효화한다. 별도 캘린더 알림의 권한은 유지한다.

## 먼저 챙겨보기

Google 연결만으로 자동 확인을 켜지 않는다. 사용자가 설정에서 먼저 챙겨보기의 하루 한 번 방식을 따로 켜고 Google도 연결한 경우, Tada는 소유자 시간대 오전 9시부터 오후 9시 사이 하루 한 번 같은 모델과 기존 사용량 한도로 받은편지함·기본 캘린더의 위 범위를 확인할 수 있다. 이 검사는 대화가 비어 있거나 바뀌지 않았어도 실행된다. 따라서 외부 조회와 모델 사용이 하루에 한 번 발생할 수 있고, 원격 데이터가 바뀌었을 때만 실행된다고 보장하지 않는다. 새 제안이 없다는 모델 응답은 조용히 기록되며 화면 알림으로 보내지 않는다. 먼저 챙겨보기를 끄면 이후 배경 확인은 중단된다.

## 호스트 설정과 데이터 보관

Google OAuth 설정은 Tada 전용 데스크톱 앱 자격 증명을 호스트 운영자가 한 번 준비한다. 승인된 앱 설정은 기존 연락 기록의 개인 디렉터리에 `google-oauth-client.enc`로 암호화해 보관할 수 있다. 다음 `npm start`는 같은 기록의 기존 보호 키로 이 파일을 읽으므로 별도 암호나 환경 변수 재입력이 필요 없다. 사용자가 화면에 키를 입력하거나 다른 앱의 자격 증명을 가져오는 기능은 없다. 선택적인 설정 파일이 없으면 기존 대화는 정상적으로 열리고 Google 연결만 비활성화된다.

호스트의 명시적 `TADA_GOOGLE_OAUTH_CLIENT_ID`와 선택적인 `TADA_GOOGLE_OAUTH_CLIENT_SECRET`은 저장값보다 우선한다. ID만 지정하면 secret은 빈 값으로 사용하며 저장된 secret을 섞지 않는다. ID를 비우고 secret도 지정하지 않거나 비우면 Google 앱 설정을 비활성화한다. secret만 지정하거나 잘못된 ID를 지정하면 저장값으로 되돌아가지 않고 오류를 알린다. 환경 변수 값은 자동으로 저장하지 않는다. 기존 파일이 있다면 환경 변수 override 중에도 먼저 무결성을 검사하며, 손상된 파일을 없는 설정으로 취급하거나 덮어쓰지 않는다.

초기 준비는 실행 중인 Tada를 종료한 뒤 `google-client-config.mjs`의 `saveGoogleClientConfig({ data, passphrase, client, route })`를 호스트 운영자가 사용한다. `client`는 승인된 Tada 전용 `{client_id, client_secret}`뿐이며, `passphrase`는 이 기록을 여는 기존 `contactStorageKey`의 결과, `route`는 같은 기록의 기존 route다. helper가 `initialize:false`로 해당 ContactStore를 직접 열어 기존 키와 단일 소유권을 확인하며 v5·v6 기록만 허용한다. 이미 Google 계정 자격 증명이 있거나 파일이 있으면 추가·교체를 거절하므로, 초기 파일 추가로 기존 환경 변수 기반 계정을 다른 앱에 다시 묶지 않는다. 개인 계정의 Google 연결 동의와 자료 접근은 이후 설정 화면에서 별도로 진행한다.

파일 형식은 version 1의 salt와 암호문뿐이다. 목적·버전을 묶은 AAD와 별도 scrypt 파생 키로 AES-256-GCM을 사용하며, 평문 client 설정·키는 저장하지 않는다. 암호문을 소유자 전용 0600 임시 파일에 완전히 기록·동기화한 뒤, 기존 파일을 교체하지 않는 배타적 링크로 게시하고 임시 이름을 제거한다. 쓰기·동기화 실패 시 이 호출이 만든 임시 파일만 정리하므로 불완전한 최종 파일이 시작과 재시도를 막지 않는다. 게시 직후 프로세스가 종료돼 두 링크가 남았으면, 다음 시작은 같은 저널의 단일 소유권과 복호화·내용 검증을 거쳐 같은 inode인 전용 임시 이름만 제거한다. 다른 저널·잘못된 키·임의의 하드 링크는 복구 대상으로 받아들이지 않는다. 읽기는 16 KiB로 제한하고 링크·다중 하드 링크·허용되지 않은 Unix 소유권/접근 권한·알 수 없는 버전/필드·잘못된 키·변조를 거절한다. 저장 디렉터리는 이미 존재하는 개인 기록 위치여야 한다. 이 별도 파일은 SQL v1–v5 문자열, `assistance_settings`, 대화 route와 Google 사용자 토큰을 변경하지 않으며 기록 이전을 일으키지 않는다. 준비 helper가 저널을 열 때에는 기존 ContactStore의 중단 작업 복구 규칙이 그대로 적용된다. 문제가 있으면 시작 화면은 내부 코드 대신 보호 키·설정 백업이나 파일 권한을 복구하도록 안내한다.

기존 v1–v4 연락 기록에서는 Google 연결을 시작하기 전에 기록 업데이트가 필요하다. 화면은 연결 버튼을 비활성화하고 Tada를 다시 열어 백업 후 업데이트하도록 안내하며, 직접 연결 요청도 인증 창이나 네트워크 요청 전에 `CONTACT_ASSISTANCE_UPGRADE_REQUIRED`로 거절한다. 기존 명시적 백업 업데이트 경로만 사용하며, 연결 요청이 기록을 자동 이전하거나 일시적 오류 재시도를 유도하지 않는다. 새 v5 기록의 연결 경로는 그대로다.

인증은 임의 포트의 `127.0.0.1` callback, 시스템 브라우저, state와 S256 PKCE를 사용한다. state는 UTF-8 바이트 길이와 값을 비교하며, 인증에 영향을 주는 `state`·`code`·`error` 중복 필드는 거절한다. Google의 추가 응답 필드는 [공식 code-model 안내](https://developers.google.com/identity/oauth2/web/guides/use-code-model)에 따라 무시하며 계정·권한 근거로 사용하지 않는다. callback 종료 후 완료 페이지를 방문하지 않아도 리스너는 정리된다. Refresh token은 기존 연락 저널 v5의 암호화된 `assistance_settings`에 보관되고, access token은 호스트 메모리에만 둔다. Gmail/Calendar 도구의 원문 응답은 다음 대화를 위한 암호화 문맥에 남기지 않는다. 답변과 출처 식별 정보는 기존 대화와 함께 보존되므로 모델이 답변에 옮긴 내용은 기록에 남을 수 있다. DB v1–v5 계약 문자열과 기존 기록은 바꾸지 않으며, 새 연결을 위해 기존 기록을 자동 이전하지 않는다.

## 검증과 배포 제한

추가 회귀는 합성 프로젝트 전체 토큰 회수가 끝난 뒤 재연결하고 실제 API 조회가 성공하는지, 대기 중 인증 취소가 브라우저·토큰 교환을 막는지 확인한다. 합성 회수 timeout이 대기를 해제한 뒤에도 원격 회수 불확실성을 보존하고 자동 재시도하지 않는지, 자격 증명 없는 인증 취소 중 일반 대화가 완료되는지도 검사한다.

코드와 테스트는 로컬 합성 OAuth/API 응답 및 SQLite 저널로 연결 경로, 다중바이트·중복 state 거절, callback 정리, 범위 검사, 재시작, 인증·읽기 취소와 출처 재확인을 확인한다. 늦은 revoke 완료와 새 대화·OAuth 경합, 갱신 권한 축소의 영속 차단과 재연결 회복, 갱신·API의 합성 deadline·사용자/epoch 취소 및 잘못된 응답의 복구 상태도 검사한다. 긴 한글·이모지 20개 목록과 본문, 긴 과거 대화에서의 도구 배치 실패는 실제 네이티브 도구 스키마 및 구독 요청 직렬화와 함께 문맥 한도를 검사한다. 실제 Rust broker 검사는 `TADA_TEST_READ_BROKER`에 컴파일된 실행 파일의 절대 경로를 지정해 실행하며, 혼합 배치의 파일 발췌와 발췌 바깥 원본 변경 거절을 확인한다. MIME B/Q 헤더, UTF-8·EUC-KR·Latin 본문, 인코딩 불가와 별도 저장·부분 본문·빈 plain alternative, mixed 본문과 파일명 없는 첨부 제외도 검사한다. metadata/full 받은편지함 이탈, 첫 연결 취소·재시도, 미연결 상태의 네이티브 출처 인용, 과거 출처만으로 수행하는 외부 읽기 차단, 연결을 소유하지 않은 기기의 취소와 저장 문서·Google 혼합 인용의 보수적인 최신성 표시도 회귀에 포함한다. 이것은 실제 계정 로그인·모델 답변·실제 Google 데이터 접근의 증거가 아니다.

Google은 `gmail.readonly`를 제한된 범위로 분류한다. 공개 배포에는 Google의 앱 검증과 보안 평가 등 추가 요건이 적용될 수 있다. 이 저장소의 연결 구현만으로 공개 배포 자격이나 Google 승인을 주장하지 않는다. 실제 배포 전 [제한 범위 검증 안내](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)와 현재 배포·데이터 처리 방식에 적용되는 요건을 확인해야 한다. 데스크톱 loopback OAuth는 [Google Native App OAuth 문서](https://developers.google.com/identity/protocols/oauth2/native-app), 필요한 권한은 [Gmail scope 안내](https://developers.google.com/workspace/gmail/api/auth/scopes)와 [Calendar events.list](https://developers.google.com/calendar/api/v3/reference/events/list?hl=en)에 따른다.
