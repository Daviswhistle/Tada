# 창을 닫은 뒤에도 같은 비서에게 연락하기

**2026-10-07:** 최신 연락 DB v4와 별도 승인한 일회성 로컬 재확인은 [재확인 안내](contact-reviews.md)를 따른다. 아래 메시징 구현의 기존 시험·미검증 범위는 그대로 구분한다.
2026-10-05 · 실행 가능한 개발용 연락 경로. 실제 Telegram 계정·휴대폰 발송 검증은 **미실행**이다.

이번 구현은 기존 연락 호스트에 Telegram 개인 채팅을 연결한다. 메시징용 모델이나 별도 대화를 만들지 않는다. 휴대폰에서 평소 말하듯 요청하고, PC 브라우저에서 앞선 대화와 결과를 확인하고, 호스트를 재시작한 뒤 다시 휴대폰에서 말을 이어가는 동일한 경로다. Telegram은 첫 연락 채널 선택일 뿐 Tada의 제품 정의가 아니다. 비서의 업무 능력과 기억·후속 행동을 계속 이 대화에 연결한다.

## 후속 추가: 같은 업무를 기록하고 다시 연락하기

연락 호스트 v3에는 [맡긴 일과 일회성 확인 알림](contact-followups.md)이 추가됐다. 대화에서 나온 제안은 `/confirm PROPOSAL_ID` 또는 브라우저 확인으로 확정한다. 이후의 조회는 일반 대화로 하고, 변경도 같은 업무의 새 버전으로 제안한다. `/cancel`은 기존처럼 답변 처리 요청만 취소한다. 이미 확정한 업무·알림의 취소와 혼동하지 않는다. 아래 v1→v2 설명은 이전 메시징 전환의 기록이며, 최신 실행 파일의 `--upgrade-contact`는 v2→v3까지 백업 후 전환한다.

## 사용자가 경험하는 것

호스트에서 본인 전용 봇과 개인 채팅을 한 번 연결하면 이후 메시지는 같은 대화에 접수된다. 접수 후에는 연락 화면을 열어 둘 필요가 없다. 처리 결과는 호스트가 저장한 뒤 개인 채팅으로 돌려보낸다. 브라우저에 있는 대화와 Telegram에 따로 설명할 필요가 없다.

**Telegram으로 맡긴 요청에는 답변 본문을, 브라우저로 맡긴 요청에는 본문 없는 도착 알림을 보낸다.** PC에서 본 사적인 내용을 단순 완료 알림으로 외부에 복사하지 않기 위해서다. 다만 Telegram에서 이전 대화에 대해 질문하면 답변에 그 대화·허용된 자료의 내용이 포함될 수 있다. 이 데이터 흐름을 연결 전에 동의한다. 기존 브라우저 기록 전체를 연결 직후 채팅으로 보내지는 않는다.

채팅의 `/cancel`은 이 채팅에서 접수한 최근 대기·실행 요청을 취소한다. `/stop`은 이 Telegram 연결을 폐기한다. 다른 사람에게 보낼 대상·문구를 모델이 정하는 전송 도구는 등록하지 않는다. 일반 대화의 의미를 미리 짜 둔 문구별 스크립트에 맞추지 않는다. 두 명령은 모델 작업과 별개인 명시적 연락 제어다.

## 개발용 연결

원래 연락 호스트와 동일하게 이미 준비한 로컬 Ollama 모델을 사용한다. 아래 `YOUR_INSTALLED_LOCAL_MODEL`은 실제 설치 모델 ID로 바꾼다. 새 기록을 만들 때만 `--init`을 사용한다.

```sh
npm ci --ignore-scripts
npm run contact -- --data ./tada-contact-private --init --model YOUR_INSTALLED_LOCAL_MODEL --telegram
```

소유자가 [Telegram 공식 봇 생성 안내](https://core.telegram.org/bots/features#botfather)에 따라 **자신만 사용하는 봇**을 준비한다. 토큰은 이 채팅이나 명령행에 붙이지 않고 실행 중인 Tada 호스트의 숨김 입력란에 입력한다. Tada는 다른 프로그램·환경변수에서 봇 토큰을 찾거나 봇 계정을 자동으로 만들지 않는다. 토큰은 이번 프로세스의 신뢰된 통신 객체에만 보관하며 자동 시작용 영속 비밀 저장은 아직 없다.

호스트는 `getMe`로 토큰에 결합된 봇 ID를 확인하고 `getWebhookInfo`로 기존 webhook이 없는지 검사한다. 다른 서비스가 사용 중인 webhook은 삭제하지 않고 거절한다. 다른 poller와 충돌하면 소유자가 원인을 확인하도록 연락 경로를 중지한다. 전용 봇을 사용하고 봇 토큰은 외부 HTTP 로그·역방향 프록시 로그에 남기지 않는다.

동의 후 호스트가 출력한 5분 유효 일회용 링크를 본인 Telegram 앱에서 연다. 이때 호스트에 표시되는 연결 요청의 사용자 ID를 확인하고 다음 명령으로 승인한다.

```text
/telegram-approve HOST_DISPLAYED_CANDIDATE_ID
```

`CANDIDATE_ID`는 호스트가 실제 표시한 값이다. 링크를 안다는 이유만으로 대화 접근권이나 실행권을 발급하지 않는다. 승인 후부터 해당 개인 사용자만 메시지를 맡길 수 있다. `/telegram-pair`는 새 연결 요청 링크, `/telegram-status`는 현재 연락 상태를 보여준다. 기존 `/devices`와 `/revoke DEVICE_ID`도 같은 연결에 적용된다. 접근 수명은 기존 기기와 같은 30일이며, 해제·만료 후에는 명시적으로 다시 연결한다.

재시작 때는 같은 데이터·모델·자료 범위로 `--init` 없이 시작하고 암호와 토큰을 다시 입력한다. 봇 ID가 바뀌어도 기존 채팅을 새 봇으로 자동 이전하지 않는다. `--telegram` 없이 실행하면 브라우저는 계속 쓸 수 있지만 Telegram 수신·알림 전송은 하지 않는다.

```sh
npm run contact -- --data ./tada-contact-private --model YOUR_INSTALLED_LOCAL_MODEL --telegram
```

**Telegram 경로는 호스트의 외부로 나가는 HTTPS 연결만 사용한다.** 휴대폰용 공개 HTTP 포트나 webhook/tunnel을 열지 않는다. 반면 기존 브라우저를 밖에서 열려면 별도로 준비한 사설 HTTPS/VPN 설정이 여전히 필요하다. 봇용 발송이 사용자 휴대폰 OS에서 알림으로 표시되는지는 Telegram·기기 알림 설정에 달려 있다. 코드가 알림 표시나 열람까지 확인했다고 기록하지 않는다.

## 기존 연락 기록의 전환

직전 패키지의 연락 DB는 v1이다. 일반 시작은 그 기록을 계속 읽되, 메시징을 켜려면 명시적으로 백업·전환해야 한다.

```sh
npm run contact -- --data ./tada-contact-private --model YOUR_INSTALLED_LOCAL_MODEL --upgrade-contact --telegram
```

기존 파일과 동일한 암호로 연 뒤, 새로운 무작위 이름의 `before-messaging-…sqlite`에 SQLite online backup을 만들고 동기화한다. 이후 하나의 트랜잭션으로 메시징 테이블·schema hash·버전을 추가한다. 실행 중인 요청이 있으면 전환하지 않는다. v1 대화와 기기 ID를 보존하고 v2에서 이전 버전으로 몰래 내려가지 않는다. 이 연락 DB v2는 기존 Rust 작업 DB의 버전과 별개다.

## 실행·전송 기록의 의미

수신에는 봇·개인 채팅·message ID로 만든 안정적인 요청 ID를 사용한다. **로컬 접수 후에만 다음 update offset을 확인**하므로, 접수 응답 손실이나 같은 메시지 재수신으로 새 모델 작업을 만들지 않는다. 취소 명령은 최초에 고른 대상도 기록한다. 오래된 `/cancel`이 재수신됐을 때 그사이 접수한 다른 일을 취소하지 않는다.

결과 전송 대기열은 암호화된 기존 답변으로부터 다시 만들 수 있다. 그 안의 `queued → sending`을 커밋한 뒤에만 API에 요청한다. 정상 영수증은 봇·개인 채팅·메시지 ID·본문 해시가 일치해야 `sent`로 기록한다. 이는 API가 메시지를 수락했다는 뜻이며 상대가 읽었다는 뜻은 아니다.

네트워크 응답 손실이나 `sending` 상태에서의 호스트 종료는 `unknown`으로 남긴다. Telegram의 `sendMessage`에 이 구현이 활용할 멱등 키·정확한 조회 경로가 없으므로 **그 메시지는 자동 재발송하지 않는다**. 긴 답변의 앞부분이 불확실하면 후속 조각도 보내지 않는다. 전체 답변은 브라우저 대화에 보존하고 불확실한 알림 수를 표시한다. 명시적으로 거절된 429의 유효한 `retry_after`만 저장한 시각 이후 재시도한다. 인증 거절은 해당 연락 권한을 폐기한다.

이 경로는 대화 호스트의 전송 기록을 사용한다. 기존 Rust 외부 행동 원장을 우회해 일반적인 이메일·결제·수정 권한을 준 것은 아니다. **과거 v2 DB 백업 전체를 임의로 되돌렸을 때 후속 메시지 발송 사실까지 판별하는 독립 복구 증거는 아직 없다.** 발송 후의 과거 백업을 자동 실행용으로 복원하지 않는다. 수동 복구에는 대상 확인과 새 연결 검토가 필요하며, 이 패키지를 외부 변경 일반화나 안전한 전체 백업 복원 기능으로 확대하지 않는다.

## 개인정보와 지원 범위

표준 HTTPS Bot API를 통한 일반 개인 채팅이다. Secret Chat이나 종단간 암호화라고 표시하지 않는다. Telegram 서버는 채팅 메시지와 전달한 답변을 처리하며, 로컬 DB 암호화가 Telegram의 보관을 없애지는 않는다. 기기 알림 미리보기 설정도 별도다. 로컬에서는 채팅 ID·사용자 ID, 발송 본문·영수증, 이전 대화 문맥을 암호화하고 모델과 브라우저에는 봇 토큰을 주지 않는다. 기기·상태·시각 등 일부 메타데이터는 기존 저장 방식대로 남는다.

현재 수신은 승인된 개인 채팅의 텍스트만 처리한다. 그룹, 타인, 봇 대리 호출, forwarded 메시지, 편집 이벤트는 실행 명령으로 사용하지 않는다. 음성·사진·파일은 다운로드나 추정 전사 없이 지원하지 않는다고 알린다. 송신은 일반 텍스트이고 링크 미리보기·형식 해석을 끄며, UTF-16 조각 경계에서 Unicode 문자를 자르지 않는다.

계속 실행되는 호스트와 준비된 모델이 필요하다. Telegram 서버의 미수신 update 보관은 공식 문서상 최대 24시간이다. 호스트가 더 오래 꺼져 있으면 모든 메시지가 나중에 접수된다고 약속할 수 없다. 복구된 대기 작업과 사용량은 유지하지만 현재의 64회 모델 요청/14 KiB 문맥 제한, 장기 기억 관리, 예약·회신 대기·후속 재개, 실제 메일·일정·일반 도구, 음성·전화와 무인 호스팅은 남아 있다.

## 검증

```sh
node --experimental-strip-types --test packages/engine/tests/contact.test.mjs packages/engine/tests/telegram-contact.test.mjs
npm run contact -- --help
```

격리된 Linux에서 Node 22.16.0으로 검사했다. 기존 20개와 새 30개 함수가 통과했다. 새 시험은 실제 SQLite 파일, Node HTTP 서버·클라이언트, 브라우저용 HTTP API와 Telegram API 형태의 **로컬 모의 서버**를 함께 사용한다. 모델 답변은 합성이다. 실제 bot token, 실제 Telegram 발송, 실제 휴대폰과 Windows 실행, 실제 모델을 통한 이 연락 경로 검증, 전체 저장소 CI는 미실행이다.

실제 자식 프로세스를 전송 전, sending 커밋 후, 독립 효과 저장 후, 영수증 커밋 후의 네 경계에서 강제 종료하고, 독립 효과 DB와 복원된 연락 기록을 대조했다. 여섯 잘못된 API 응답, 입력 종료·명시적 동의, webhook 충돌, rate limit, 취소 재수신, 계정·채팅 결합, 데이터 암호화와 Unicode 조각도 검사한다. 내부 시나리오는 테스트 함수 수에 중복 계산하지 않는다.

브라우저가 없는 동안 결과 전송을 시작하는 자동 처리 루프와 그 프로토콜을 검사한 것이며, 합성 모델과 Telegram fixture가 실제 계정의 대화 품질이나 폰 알림을 증명하지 않는다. 다음 실제 검증은 소유자가 명시적으로 준비한 전용 봇·로컬 모델·휴대폰으로 동일한 기기 전환/재시작 시나리오를 수행하는 것이다.
