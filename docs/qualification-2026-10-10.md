합성 Gmail과 실제 ContactService·Chrome으로, 메일을 읽은 대화 모델이 공유 페이지의 일반 입력란에 본문을 넣으면 자동 저장 요청까지 전달되는 기존 경로를 재현했다. 브라우저 도구를 별도 문맥으로 옮겨 현재 사용자 요청과 공유 자료만 받도록 수정했다. 일반 편집은 추가 승인 없이 실행하며 같은 요청의 중복 호출은 재실행하지 않는다. 메일·과거 대화에서 내용을 옮기는 별도 승인 UI는 이 단위에 포함되지 않는다. 따라서 기존 A08의 과거 문구 참조 성공을 변경 후 경로의 성공 근거로 재사용하지 않는다.

## 출처 내용을 웹사이트에 옮기는 미리보기

같은 대화에서 과거 기록·메일 내용을 정확한 텍스트나 파일로 준비하고, 요청한 기기의 미리보기에서 승인한 바이트만 적용하는 경로를 추가했다. 승인에는 모델 호출이 없고, 일반 현재 화면 편집은 계속 격리된 편집기로 바로 처리한다. 원래 문서·입력값이 바뀌면 적용하지 않는다. 미리보기의 내용·도구 인자는 다음 모델 체크포인트에 보존하지 않으며 승인 후의 실제 action 영수증은 재시작 뒤 대화와 기록 조회에서도 볼 수 있다.

[검증 기록](browser-transfer-verification.json): 최종 전체 Node 1,600개·Native Windows 관련 258개가 생략 없이 통과했다. 합성 Google와 실제 ContactService·Chrome의 로컬 자동 저장 시험에서 승인 전 전송 0회, 승인 후 1회, 중복 승인 추가 0회, 승인 전에 대상이 바뀌면 0회를 확인했다. 실제 Tada UI의 HTTP 승인·미승인 값 추가 거부와 1280px·390px 렌더링도 검사했다. npm ci 및 Rust fmt/clippy/workspace/process-fixtures를 다시 실행해 통과했다. 첫 전체 Node 실행의 read-broker 11개 생략은 최종 전체 실행에서 해소했다.

이는 호스트·화면 경로의 검증이며 실제 모델의 맥락 이해를 다시 수락한 결과는 아니다. 변경 이전의 A08와 영향을 받는 브라우저·파일 사례를 현재 제품의 통과로 계산하지 않는다. 물리 휴대폰, 실계정 자동 제안의 지속적 품질 평가, 공개 계정 검증과 출시 수락도 별도로 남는다.

첫 코드 검수에서 효과 기록 누적으로 일반 대화가 실패하는 문제, 적용 중 새 요청이 다음 준비를 막는 문제와 결과 표시 두 가지 오류를 재현했다. 실제 직렬화 바이트 예산으로 최신 기록을 제한하되 전체 기록은 보존하고, 무효화된 적용은 효과 기록을 마친 뒤 미리보기를 해제했다. 여러 요청이 대기할 때 새 요청 실행이 오래된 미리보기를 지우는 회귀도 추가했다. 적용 후 값 불일치와 불확실 실행을 구분하고, 과거 파일 검증은 다운로드 바이트 비교로만 표시한다. 수정 후 관련 검사 172개와 위 전체·Windows 검사를 통과했다. 중간 검사의 새 테스트 환경이 허용 문맥 한도를 잘못 선언한 실패는 정상 범위로 수정한 뒤 재실행했으며 통과로 계산하지 않았다.

두 번째 검수는 기본 모드에서 승인 결과가 모델에 전달되지 않는 문제와 긴 입력란 이름 7건의 기록 조회가 작은 문맥에서 실패하는 문제를 재현했다. 최근 효과 상태는 기록 검색 동의와 별개로 전달하고, 기록 조회는 원본을 자르지 않는 최대 8개 페이지와 다음 offset을 제공하도록 수정했다. 실제 문맥 예산에 따라 페이지를 더 작게 반환하며, 17개 기록의 전체 페이지 연결과 기본 로컬 문맥의 실제 서비스 조회를 검사했다. 전체 검사 중 추가된 도구 설명으로 두 로컬 문맥 회귀가 실패해 설명을 간결하게 고친 뒤 관련 79개 및 전체 1,572개를 다시 통과했다. Windows 관련 230개와 실제 Chrome 다섯 경로도 같은 소스로 통과했다.


세 번째 검수에서는 Google 도구가 연결된 기본 로컬 문맥에서 선택적 회상 정책이 승인 영수증을 생략하는 문제, 후속 제안 안내가 삭제한 본문을 체크포인트에 되살리는 문제, 실패한 준비를 성공한 준비로 기록하는 문제를 재현했다. 효과 기록을 필수 상태로 바꾸고 전체 기록을 보존한 채 최근 요약은 실제 직렬화 512바이트로 제한했다. 준비 상태는 실제 후보와 최종 거부 여부를 반영하며 후속 안내는 별도로 남긴다. 처음 전체 재실행에서는 필수 기록 때문에 Google와 저장 파일 조회의 문맥 회귀가 1건 발생했다. 요약을 줄인 뒤 관련 68개 및 전체 1,593개·Windows 관련 251개가 생략 없이 통과했다.

`edbfa35`의 실제 선택 구독 모델 재검증에서는 A08 두 변형과 A02/A03 네 변형 중 다섯 개가 실패했다. 총 24회 관측된 모델 요청이었다. 오래된 대상은 승인 직전 안전하게 차단했지만 모델이 재관측하지 않았고, 파일 수리는 준비 또는 새 문서 생성에서 끝나는 경우가 있었다. 이는 실패 근거로 유지하며 과거 성공을 현재 수락으로 재사용하지 않는다. 현재 수정은 준비 전에 같은 DOM·파일 조건을 읽기 전용으로 검사하고, 읽기만 한 부모 대화가 새 격리 편집기로 넘어갈 수 있도록 한다. 일반 수리는 현재 앱 관측·의미 보존·앱 동작 확인을 요구하며, 이전 자료를 옮길 때만 미리보기를 사용한다. 아래 수정 후 재검증과 별개인 실패 근거다.


수정 후 `30609ed`의 [A08 두 변형](../evals/assistant-v1/results/2026-10-10-shared-browser-transfer-second.json)은 실제 구독 모델 9회로 기계 검사와 [독립 의미 검수](../evals/assistant-v1/results/2026-10-10-shared-browser-transfer-second-review.json)를 통과했다. 첫 변형은 바뀐 입력란을 다시 찾아 정확한 미리보기를 발행한 뒤 평가자의 별도 승인으로 올바른 필드만 입력했다. 두 번째는 공용 계정 변경을 다시 관측하고 미리보기·입력 없이 개인 계정으로 돌아가도록 안내했다. 승인은 모델 응답 뒤의 평가자 행동이며 정답·승인 정보는 모델에 주입하지 않았다. 입력 후 다음 대화의 완료 설명이나 실제 계정 전환을 이 결과가 입증하지는 않는다.

[A02/A03 두 번째 실행](../evals/assistant-v1/results/2026-10-10-situated-file-transfer-second.json)은 32회 검증 한도 때문에 마지막 변형이 중단되어 전체 통과로 계산하지 않았다. 제품·fixture·판정 조건을 바꾸지 않고 검증기 기본 한도 48회로 다시 실행한 [세 번째 실행](../evals/assistant-v1/results/2026-10-10-situated-file-transfer-third.json)은 36회 모두 관측됐고 네 변형의 기계 검사를 통과했다. UTF-16 CSV와 구분자 오류는 원래 셀 의미를 유지하며 현재 앱으로 가져왔고, JSON 끝 쉼표와 코드 블록 오류는 원본·관계없는 문서를 보존하면서 현재 문서함에서 열었다. 합성 페이지가 관측한 import/open 결과이며 일반 사이트의 서버 영구 저장, 물리 휴대폰, 시장 출시 수락은 아니다. 실패·한도 중단 보고서도 함께 보존한다.


[네 변형의 독립 의미 검수](../evals/assistant-v1/results/2026-10-10-situated-file-transfer-third-review.json)와 주 세션도 현재 앱 동작 기준을 수락했다. 최종 설명은 화면에서 관측한 import/open만 보고했고 원래 파일 action의 `UNCERTAIN` 상태와 재실행 차단은 유지했다. 평가자는 원문·실제 표·열린 문서·답변을 대조했으며 범용 파일 수리나 전체 제품 수락으로 확대하지 않았다. 이 단위의 실제 모델 호출은 실패·한도 중단을 포함해 총 101회이며, 마지막 완결 검증은 A08 9회와 A02/A03 36회다.

네 번째 검수는 읽기만 한 공유 파일 본문이 공유 해제 뒤 다음 모델 입력에 남는 문제와 승인 HTTP 응답 지연이 새 미리보기까지 잠그는 문제를 재현했다. 읽은 본문과 해당 읽기 이후의 공급자 연속 문맥을 체크포인트에서 제거하되 사용자에게 보여 준 답변은 유지한다. 승인 응답은 본문 읽기까지 30초로 제한하고 결과를 조회해 복구하며, 불확실한 동일 요청을 다시 보내거나 늦은 응답으로 새 미리보기를 덮어쓰지 않는다. 원문·연속 문맥이 재시작 후 실제 구독 입력 직렬화에서도 빠지는 회귀와 응답·본문 지연 여섯 경우를 추가했다. 관련 263개, 전체 1,600개, Windows 관련 258개가 생략 없이 통과했고 실제 Chrome 다섯 경로와 공유 브라우저 smoke도 통과했다. 첫 추가 테스트의 중첩 JSON 문자열 비교 오류는 실제 도구 결과의 본문 비교로 바로잡았으며 실패 실행은 통과로 계산하지 않았다. 이번 수정은 완료된 요청의 체크포인트와 승인 화면 복구에 한정하며, 위 실제 모델의 현재 요청 내 도구 실행·평가 조건은 바꾸지 않았다.

다섯 번째 검수에서 모든 연결 기능과 효과 기록을 함께 사용할 때 기본 로컬 문맥이 초과되는 문제, 미확정 메일 상태 조회가 현재 요청의 브라우저 준비를 무효화하는 문제를 재현했다. 큰 도구 묶음은 같은 모델·한도·권한을 유지한 채 `select_tools`로 필요한 설명을 선택하도록 변경했다. 전체 기능과 이전 효과 기록을 켠 상태의 인사·텍스트 준비·파일 준비·일반 수리, 메일 본문과 저장 업무 조회를 실제 직렬화 크기로 검사했다. 이 선택은 모의 모델에서 확인했으며 실제 로컬 모델의 판단 품질을 통과로 주장하지 않는다. 구독 경로의 기존 설명·직접 호출은 변경하지 않았다.

메일의 읽기용 상태 재확인은 준비를 무효화하지 않게 했으며, 소유자의 발송·수정·폐기는 계속 무효화한다. ACCEPTED/UNCERTAIN 각각에서 상태 조회 뒤 텍스트·파일을 준비하고 추가 조회 후에도 미리보기를 유지하는 회귀를 통과했다. 실제 메일을 보내지 않았다. `npm run check`는 1,617개 모두 생략 없이 통과했다. 발송 접수 시 비동기 실행을 기다리지 않고 즉시 미리보기를 무효화하는 마지막 보강 뒤에는 관련 125개와 Native Windows 79개를 생략 없이 통과했고, Windows 검사 복사본의 전체 실행 소스 바이트 일치도 확인했다. 이전 전체 실행의 네 실패는 고정된 모의 모델이 새 도구 선택 단계를 거치지 않아 생긴 것으로, 실제 도구 계약을 따르게 수정하고 다시 검사했다. 공유 스키마·Rust·의존성은 바꾸지 않았다. 전체 제품·물리 휴대폰·일반 작업 수행의 출시 수락은 여전히 별도다.

여섯 번째 검수는 파일을 읽지 않고 페이지 관측만 한 경우에도 공급자 연속 문맥이 다음 요청으로 넘어가는 누락을 재현했다. 정리 경계를 파일 읽기와 페이지 관측에 함께 적용했다. 공유를 해제한 뒤 같은 서비스에서 이어 말하기와 재시작 후 이어 말하기를 각각 검사했고, 실제 구독 입력 직렬화에 원문·연속 문맥이 포함되지 않으면서 사용자에게 보여 준 답변은 유지됨을 확인했다. 관련 대화·브라우저·구독 검사 184개와 Native Windows 82개가 생략 없이 통과했다. Windows 복사본의 실행 소스 바이트도 동일했다. 현재 요청 안에서 관측·추론하는 방식은 그대로이며 앞선 실제 모델 평가를 새 실행으로 계산하지 않는다.

일곱 번째 검수는 새 작업이 저장될 때마다 누적된 파일 기록 전체를 다시 읽는 성능 회귀를 재현했다. 최초 요약 인덱스 구축 뒤에는 변경된 action만 갱신하며, transaction 실패 시 캐시를 폐기해 저장되지 않은 결과가 남지 않게 했다. 실제 복호화 횟수로 과거 파일 본문을 다시 읽지 않음을 확인하고, 실패 후 복구와 재시작 결과도 대조했다. 32KiB 원본·수정본 1,000건을 사용한 한 번의 로컬 측정에서 최초 구축은 468.41ms, 새 기록 추가 후 조회는 1.39ms였다(수정 전 검수 측정은 약 470ms). 전체 UI 지연이나 백분위 수락을 뜻하지 않는다. 전체 `npm run check` 1,622개와 Native Windows 관련 84개가 생략 없이 통과했고 실행 소스 바이트 일치도 확인했다.

여덟 번째 검수는 공개 조사 출처와 브라우저 처리 기록이 함께 있는 답변을 다시 읽을 때, 출처를 복원한 뒤 최종 크기가 초과되는 오류를 재현했다. 최종 응답에 출처와 안내를 넣은 뒤 처리 기록을 나누도록 수정했다. 2,600바이트 예산에서 17건 전체를 누락·중복 없이 조회하고, 너무 작은 예산으로 거부한 조회는 출처 재사용이나 소유자 맥락을 허용하지 않음을 확인했다. 관련 120개, 전체 1,623개, Native Windows 관련 85개가 생략 없이 통과했고 Windows 실행 소스 바이트 일치도 확인했다. 이번 기록 조회 수정에 실제 모델 호출이나 외부 발송은 없었다.
