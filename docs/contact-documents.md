# 같은 대화에서 문서를 만들고 수정하기

사용자는 비서를 맡겼는데 상담 상대 같은 문구와 대화 화면만 제공됐다고 지적했다. 이 변경은 실제로 남는 결과물 하나를 같은 대화에 연결한다. 문구 개선을 비서 완성으로 취급하지 않는다.

## 사용 흐름

“새 프로젝트를 시작할 때 확인할 항목을 체크리스트 문서로 만들어줘”처럼 부탁하면 모델이 일반 문서 도구를 선택해 문서를 준비하고 본문을 작성한다. 확정된 답변에는 제목·버전·내려받기 버튼이 붙는다. Markdown 또는 텍스트 파일을 받을 수 있다. “아까 문서를 한 문장으로 줄여줘” 같은 후속 요청에서는 저장된 문서를 찾아 읽고 새 버전으로 작성한다. 원본은 보존한다. 특정 문구를 실행 스크립트에 매칭하지 않는다.

기본 대화에 `list_documents`, `read_document`, `prepare_document`를 등록했다. 모델이 제목과 형식, 수정할 문서를 지정하고 최종 답변을 본문으로 작성한다. 도구의 준비 결과는 저장 완료를 뜻하지 않는다. 자료에 의존한 사실은 기존 인용 검사·자료 재확인을 통과해야 하며, 최종 답변과 문서 메타데이터가 같은 암호화 트랜잭션에서 저장돼야 내려받을 수 있다. 내려받는 파일에는 인용한 자료의 목록도 포함한다.

## 보존과 경계

문서는 기존 연락 DB의 암호화된 답변에 추가 메타데이터로 저장한다. 별도 평문 파일 저장소나 새 DB 전환은 없다. 원본 본문 해시를 저장하고 읽을 때 확인한다. 버전은 호스트가 부여하고 직전 버전을 연결한다. 목록·조회·모델 문맥에 원본 ID와 이전 버전 ID를 남겨 같은 제목의 문서도 계보로 구별한다. 이전 버전을 바탕으로 최신 버전을 조용히 덮어쓰지 않는다. 외부 공개·발송, 사용자의 임의 경로 파일 변경 권한은 생기지 않는다. 예약된 읽기 전용 재확인에는 문서 도구를 추가하지 않는다.

공급자의 구조화된 작성 거절은 대화 답변으로만 남기며 새 문서·새 버전으로 발행하지 않는다. 취소·기기 권한 폐기·중단·본문 생성 실패 뒤에는 준비만 된 문서를 완료 결과로 저장하지 않는다. 인증된 같은 소유자의 기기만 문서를 읽고 내려받을 수 있다. 브라우저에서는 문단·목록·강조·코드와 표를 표시하되 모델의 HTML·링크·이미지는 실행하거나 불러오지 않으며, 다운로드는 attachment와 no-store로 응답한다. 이름은 호스트가 생성하므로 모델의 제목을 경로나 HTTP 헤더로 사용하지 않는다.

문서 본문은 현재 4 KiB 이내의 짧은 문서다. 문서를 작성한다는 이유로 선택한 공급자의 문맥 한도나 현재 요청 한도를 늘리지 않는다. ChatGPT 문맥 크기는 실제 직렬화한 요청으로 측정해 내부 메시지와 공급자 continuation을 중복 계산하지 않는다. 도구 정의도 한도에 포함한다. 문서 조회는 메타데이터 한 줄과 본문 원문을 도구 데이터로 전달해 JSON 중첩 이스케이프를 피한다. 문서의 출처도 일반 자료 조회와 같은 인용 보정·최종 재검증을 거친다. 전체 대화·도구·본문이 한도를 넘으면 기존 중단 규칙이 적용된다. 확정된 문서 턴은 모델의 이어가기 문맥에서 제목·ID·버전의 짧은 영수증으로 바꾸고, 본문은 암호화된 답변에서 필요할 때 조회한다. 실제 관측·사용량·원래 요청·자료 증거는 보존한다. ChatGPT의 해당 턴 continuation도 함께 제거해 변형된 문맥과 공급자 상태가 충돌하지 않게 한다. 문서 조회 결과의 중복 본문도 다음 턴에 계속 쌓지 않는다.

## 검증 범위

실제 SQLite·HTTP 저장/다운로드 경로로 생성, 재시작 후 조회와 수정, 원본 보존, 다운로드 바이트 해시, 미인증/폐기된 기기 차단, 취소 후 늦은 결과 폐기, 출처 변경 시 발행 거절, 최대 본문 길이의 수정, 구독 프로토콜 문맥 복원을 검사한다. 구독 HTTP 프로토콜로 최대 길이 문서를 저장하고 재시작한 뒤 목록·조회·수정을 거치는 테스트는 각 크기 측정값이 실제 전송 요청과 같은지도 확인한다. 따옴표가 많은 본문, 동일한 제목의 서로 다른 문서 계보, 수정 시 누락 인용 보정과 출처 변경, 준비 후 공급자 거절도 회귀 검사한다. 모델은 합성이므로 이는 자연어 이해나 실제 계정의 업무 수행 품질 증명이 아니다.

실제 ChatGPT 구독과 연결 계정의 제한된 관측 및 고정 합성 환경의 행동 평가는 [현재 검증 기록](qualification-2026-10-09.md)에 구분해 기록한다. Google 연결이 설정된 연락 호스트는 최근 메일·기본 캘린더를 읽을 수 있지만, 일반적인 컴퓨터 작업, 메일 발송·일정 편집·회신 감지, 외부 문서 편집, 긴 문서와 장기 기억, 설치 프로그램과 전체 제품 인수 검증은 남아 있다. 이 기능은 문서 결과를 전달하는 한 경로이며 출시 가능한 비서라는 선언이 아니다.

## 대화에서 읽는 문서와 표

주간 업무·비교 결과의 Markdown 표는 제목 셀, 본문 셀, 강조와 출처 표시를 유지한다. 작은 화면에서는 표 전체를 좌우로 넘길 수 있다. 첫 열에 긴 업무명이 있어도 다른 열 위에 고정되어 기한이나 우선순위를 가리지 않는다. 키보드로도 표 영역에 접근해 이동할 수 있다. 저장된 본문과 내려받는 문서의 바이트는 표시를 위해 바꾸지 않는다.

파서는 고정한 markdown-it 15.0.2를 로컬에서 제공한다. [공식 안전 지침](https://github.com/markdown-it/markdown-it/blob/master/docs/safety.md)을 참고해 HTML을 끄고, 파서의 HTML 출력도 사용하지 않는다. 허용 목록의 DOM 요소만 직접 만들며 URL·원문 HTML·이미지는 실행되지 않는 읽을 수 있는 텍스트로 남긴다. 파서 오류 때는 원문 전체를 표시한다. 관련 라이선스는 앱의 third-party-notices.txt에 포함한다.

실행 중인 호스트는 시작할 때 읽은 화면·스크립트·스타일·파서 묶음을 유지한다. 디스크의 파일을 업데이트하는 중에도 같은 호스트가 서로 다른 버전의 파일을 섞어 제공하지 않는다. 새 호스트는 새 묶음을 읽는다. 이는 설치 프로그램이나 모든 재시작 시점의 무중단 배포를 보증하는 기능은 아니다.

2026-10-09에는 실제 구독 모델의 합성 업무 답변으로 1280px 및 390px 브라우저 화면을 검사했다. 작은 화면의 표 너비는 640px, 표 영역은 329px이고 페이지는 화면 너비를 넘지 않았다. 키보드 가로 이동을 확인했다. 초기 고정 첫 열은 긴 업무명에서 다른 열을 가리는 결함이 재검수에서 발견돼 제거했다. 390px 화면의 344px 표 영역에서 352px 첫 열이 다른 두 열을 덮던 상태를 재현하고, 수정 뒤 끝까지 이동하면 우선순위·기한 셀이 가림 없이 보이는지 확인했다. 이는 물리 휴대폰·Telegram 송수신 검증과 별개다. Node 회귀 892개가 생략 없이 통과했으며, HTML·이미지·링크 차단, 표 셀·출처 보존, 잘못된 표·코드 표시, 파일 변경 중 화면 묶음 일관성을 검사한다. 마지막 안내 문구·위치 조정 뒤 화면 클라이언트 40개를 다시 통과했다.
