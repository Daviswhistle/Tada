# 먼저 챙겨보기와 휴대폰 연락

2026-10-08 사용자 요청: “내가 일을 맡기지 않아도 능동적으로 나에게 도움이 되는 일을 찾아서 제시해야 해. 핸드폰에서도 연락할 수 있어야 하고.”

같은 비서의 기능을 같은 대화에 연결했다. 새 메시지가 없어도 호스트가 저장된 대화·맡긴 일·문서에서 다음에 도움이 될 제안을 찾고, Google을 연결하고 먼저 챙겨보기를 켠 경우에는 범위가 제한된 받은편지함·기본 캘린더 관측을 더할 수 있다. 휴대폰은 기존 Telegram 개인 연락 어댑터를 같은 대화에 연결한다. 메일·일정 읽기는 [Google 연결 안내](google-connection.md)를 따른다. 이 구현은 메일·일정 쓰기, 현재 화면 감시, 항상 켜진 서버나 실제 휴대폰 검증을 완료했다는 뜻은 아니다.

## 화면에서 사용하기

`npm start`로 같은 대화를 연다. 기존 기록은 화면의 **백업 후 업데이트**를 본인이 선택해야 v5로 전환된다. 이전 v1–v4 스키마 문자열과 암호화 형식은 보존하며, 단계별 백업을 만든다. 신규 기록은 v5다. 기능 설정은 **설정**에 있다. **먼저 챙기기 / 연결된 계정 / 연락과 알림**으로 나누며, 설정 창은 키보드 Escape 또는 닫기로 나간다. 닫으면 입력 중인 Telegram 키는 비우고 대화로 돌아간다.

**먼저 챙겨보기 켜기**를 한 번 선택하면 현재 모델·계정과 같은 대화에서 계속 적용된다. 이후 매 확인마다 승인을 요구하지 않는다. 컴퓨터의 설정 시간대에서 오전 9시부터 오후 9시 사이 하루 최대 한 번 확인한다. Google이 연결되지 않았으면 새 대화나 업무 변경이 있을 때만 확인하고 같은 맥락을 반복 호출하지 않는다. Google이 연결되어 있으면 외부 내용이 바뀌었는지 알기 위해 대화가 비어 있거나 변하지 않았어도 하루 확인을 수행한다. 이때 메일·캘린더 조회와 모델 사용이 생길 수 있으며, 원격 데이터가 바뀐 경우에만 요청된다고 보장하지 않는다. 첫 확인은 다음 호스트 확인 주기에 시작한다. 근거가 없거나 이미 제안한 내용이면 조용히 기다리며, `NO_NEW_SUGGESTION` 응답은 대화 UI와 연락 대기열에 노출하지 않는다. 일일 대기 시각은 재시작이나 설정 변경 뒤에도 보존한다. 연결된 Google 계정이 있으면 두 목록의 조회가 모두 성공해야 확인을 완료할 수 있다. 읽지 않고 답하거나 `NO_NEW_SUGGESTION`으로 끝내려 하면 같은 4회 한도 안에서 한 번 교정하고, 계속 누락하면 실패로 남긴다. 빈 목록은 성공 관측이지만, 조회 오류를 빈 목록으로 취급하지 않는다. 오늘·내일 일정, 메일에서 확인한 명시적 기한, 미완료 업무를 우선 챙기도록 지시하며 기한 접근과 일정 변경은 이전에 언급한 일을 다시 알려줄 근거다. 이는 일일 확인 시점의 리마인드이며 특정 시각의 자동 예약 생성은 아니다. 의미상 중복 억제와 실제 모델의 유용성은 별도 평가가 필요하다.

한 확인은 최대 4회의 모델 호출을 사용하고 기존 전체 저널 한도를 공유한다. 남은 모델 요청이 4회 이하면 새 자동 확인을 멈춰 직접 대화에 남긴다. Google 관측은 연결 계정에서 최근 7일 받은편지함 최대 20개와 앞으로 7일 기본 캘린더 최대 20개로 제한되며, 더 많은 결과는 잘릴 수 있다. 현재 저널 전체 64회 한도와 작은 문맥 제한은 여전히 개발용 제약이며 장기 제품 수준의 사용량·기억 관리는 남아 있다. 다른 모델, 계정, API 결제나 새 자료 범위로 바꾸지 않는다.

제안은 사람이 보낸 요청과 구분해 **먼저 챙겨봤어요**로 표시된다. 실제 작업 수행은 이후 사용자가 맡기는 대화에서 진행하며, 이 권한으로 파일·업무를 바꾸거나 타인에게 연락할 수 없다. 설정에서 끄거나 승인한 기기 연결이 해제·만료되면 대기·실행 중 확인과 아직 보내지 않은 알림을 중지한다. 진행 중 새 대화/업무 변경이 오면 오래된 제안은 채택하지 않는다. 이미 보낸 알림은 회수하지 못하며, 전송 결과가 불명확하면 재전송하지 않는다.

## 휴대폰 연결

설정의 **휴대폰에서 연락하기**에서 Telegram의 [BotFather](https://t.me/BotFather)를 열어 Tada 전용 봇을 만들고 받은 연결 키를 붙여 넣는다. Telegram이 제공하는 절차는 [공식 안내](https://core.telegram.org/bots/tutorial)를 따른다. 이 단계는 아직 계정 연결의 사용자 수고로 남아 있으며, Tada가 봇을 자동 생성하거나 타 앱의 토큰을 가져오지 않는다.

**동의하고 연결하기**를 누른 뒤 연결 링크를 휴대폰에서 열어 시작한다. 컴퓨터 화면에 뜬 요청이 본인의 것인지 확인하고 **내 휴대폰이 맞아요**를 누른다. 승인 전에는 대화 접근·모델 실행·발송을 허용하지 않는다. 이후 Telegram에서 평소처럼 말하면 기존 대화와 업무를 이어간다. 토큰은 같은 저널에 암호화해 저장하며 브라우저 저장소·API 상태·모델 문맥에 반환하지 않는다. 재시작하면 본인이 연결한 어댑터를 복구한다. 일시적인 연결 오류에는 화면의 **저장된 연결로 다시 시도**를 눌러 암호화된 키를 재사용하며 다시 입력할 필요가 없다. 설정에서 연결 해제하면 저장한 키를 제거하고 기기를 폐기한다. 기존 고급 `--telegram` 경로는 실행 중 메모리만 쓰는 방식으로 유지한다.

Telegram에서 보낸 요청의 답변은 그 채팅으로 돌아간다. 브라우저에서 시작한 결과와 능동 제안은 본문 없는 도착 알림을 보낸다. 휴대폰에서 이어 물으면 같은 대화의 내용을 확인할 수 있다. 봇이 타인과의 일반적인 외부 연락 수단이 되지는 않는다. 전화·음성·사진·파일 입력은 아직 지원하지 않는다. 컴퓨터가 꺼지거나 잠들면 실시간 대화·능동 확인도 멈춘다. 별도의 상시 호스팅이나 외부 공개는 설정하지 않았다.

## 내부 계약과 검증

v5는 암호화 설정과 `proactive_runs`를 추가한다. 승인 epoch·현재 기기·입력 상태를 모델 요청 전, 도구 조회 전, 결과 저장 전과 전달 대기열에서 검사한다. run의 grant 연결도 암호화된 payload와 대조한다. 저장 문서의 인용은 해당 문서를 이번 확인에서 읽었고 내용 해시와 기록된 출처가 그대로일 때만 채택한다. `saved_document_sources_checked`로 구분해 화면에도 당시 기록임을 표시한다. 이것은 외부 파일의 현재 상태를 재관측한 `cited_sources_rechecked`가 아니며, 외부 읽기 권한을 추가하지 않는다. Google 출처를 쓴 답변은 현재 같은 계정에서 메일·일정을 다시 읽고 해시가 일치할 때만 채택한다. 중단·불명확한 확인은 자동 재실행하지 않는다. 배경 제안이 없을 때도 실제 사용량은 보존한다.

검증은 실제 SQLite, HTTP, 타이머, 브라우저 JS와 로컬 Telegram 시뮬레이터를 사용한다. Google 연결 회귀는 합성 OAuth/Gmail/Calendar 서버와 실제 SQLite 저널로 PKCE·scope 검사, 재시작·refresh, 제한된 source reads, 출처 재확인, 연결 해제 중 지연된 결과 차단을 다룬다. 합성 모델의 문장은 실제 모델의 유용성 증거가 아니다. Google 계정 연결과 대화 중 문서 저장의 한정된 실계정 결과는 [검증 기록](qualification-2026-10-07.md)에 따로 남겼다. 일일 자동 확인의 실제 제안 품질, Telegram 계정·휴대폰 송수신·항상 켜진 운영과 제품 평가 16건은 미완료다.
