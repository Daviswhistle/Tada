# 먼저 챙겨보기와 휴대폰 연락

2026-10-08 사용자 요청: “내가 일을 맡기지 않아도 능동적으로 나에게 도움이 되는 일을 찾아서 제시해야 해. 핸드폰에서도 연락할 수 있어야 하고.”

같은 비서의 두 기능을 연결했다. 새 메시지가 없어도 호스트가 저장된 대화·맡긴 일·문서에서 다음에 도움이 될 제안을 찾는다. 휴대폰은 기존 Telegram 개인 연락 어댑터를 같은 대화에 연결한다. 이 구현은 메일·일정·현재 화면 감시나 항상 켜진 서버, 실제 휴대폰 검증을 완료했다는 뜻은 아니다.

## 화면에서 사용하기

`npm start`로 같은 대화를 연다. 기존 기록은 화면의 **백업 후 업데이트**를 본인이 선택해야 v5로 전환된다. 이전 v1–v4 스키마 문자열과 암호화 형식은 보존하며, 단계별 백업을 만든다. 신규 기록은 v5다. 기능 설정은 **설정**에 있다.

**먼저 챙겨보기 켜기**를 한 번 선택하면 현재 모델·계정과 같은 대화에서 계속 적용된다. 이후 매 확인마다 승인을 요구하지 않는다. 컴퓨터의 설정 시간대에서 오전 9시부터 오후 9시 사이에, 새 대화나 업무 변경이 있을 때 하루 최대 한 번 확인한다. 첫 확인은 이 시간대의 다음 호스트 확인 주기에 시작한다. 근거가 없거나 이미 제안한 내용이면 조용히 기다리도록 모델에 지시하며, `NO_NEW_SUGGESTION` 응답은 대화 UI와 연락 대기열에 노출하지 않는다. 새 변화가 없는 맥락은 재시작이나 설정을 껐다 켠 뒤에도 반복 호출하지 않는다. 일일 대기 시각도 보존한다. 같은 상황에서 무엇이 유용한지에 대한 실제 모델의 판단 품질은 별도 평가가 필요하다.

한 확인은 최대 4회의 모델 호출을 사용하고 기존 전체 저널 한도를 공유한다. 남은 모델 요청이 4회 이하면 새 자동 확인을 멈춰 직접 대화에 남긴다. 현재 저널 전체 64회 한도와 작은 문맥 제한은 여전히 개발용 제약이며 장기 제품 수준의 사용량·기억 관리는 남아 있다. 다른 모델, 계정, API 결제나 새 자료 범위로 바꾸지 않는다.

제안은 사람이 보낸 요청과 구분해 **먼저 챙겨봤어요**로 표시된다. 실제 작업 수행은 이후 사용자가 맡기는 대화에서 진행하며, 이 권한으로 파일·업무를 바꾸거나 타인에게 연락할 수 없다. 설정에서 끄거나 승인한 기기 연결이 해제·만료되면 대기·실행 중 확인과 아직 보내지 않은 알림을 중지한다. 진행 중 새 대화/업무 변경이 오면 오래된 제안은 채택하지 않는다. 이미 보낸 알림은 회수하지 못하며, 전송 결과가 불명확하면 재전송하지 않는다.

## 휴대폰 연결

설정의 **휴대폰에서 연락하기**에서 Telegram의 [BotFather](https://t.me/BotFather)를 열어 Tada 전용 봇을 만들고 받은 연결 키를 붙여 넣는다. Telegram이 제공하는 절차는 [공식 안내](https://core.telegram.org/bots/tutorial)를 따른다. 이 단계는 아직 계정 연결의 사용자 수고로 남아 있으며, Tada가 봇을 자동 생성하거나 타 앱의 토큰을 가져오지 않는다.

**동의하고 연결하기**를 누른 뒤 연결 링크를 휴대폰에서 열어 시작한다. 컴퓨터 화면에 뜬 요청이 본인의 것인지 확인하고 **내 휴대폰이 맞아요**를 누른다. 승인 전에는 대화 접근·모델 실행·발송을 허용하지 않는다. 이후 Telegram에서 평소처럼 말하면 기존 대화와 업무를 이어간다. 토큰은 같은 저널에 암호화해 저장하며 브라우저 저장소·API 상태·모델 문맥에 반환하지 않는다. 재시작하면 본인이 연결한 어댑터를 복구한다. 일시적인 연결 오류에는 화면의 **저장된 연결로 다시 시도**를 눌러 암호화된 키를 재사용하며 다시 입력할 필요가 없다. 설정에서 연결 해제하면 저장한 키를 제거하고 기기를 폐기한다. 기존 고급 `--telegram` 경로는 실행 중 메모리만 쓰는 방식으로 유지한다.

Telegram에서 보낸 요청의 답변은 그 채팅으로 돌아간다. 브라우저에서 시작한 결과와 능동 제안은 본문 없는 도착 알림을 보낸다. 휴대폰에서 이어 물으면 같은 대화의 내용을 확인할 수 있다. 봇이 타인과의 일반적인 외부 연락 수단이 되지는 않는다. 전화·음성·사진·파일 입력은 아직 지원하지 않는다. 컴퓨터가 꺼지거나 잠들면 실시간 대화·능동 확인도 멈춘다. 별도의 상시 호스팅이나 외부 공개는 설정하지 않았다.

## 내부 계약과 검증

v5는 암호화 설정과 `proactive_runs`를 추가한다. 승인 epoch·현재 기기·입력 상태를 모델 요청 전, 도구 조회 전, 결과 저장 전과 전달 대기열에서 검사한다. run의 grant 연결도 암호화된 payload와 대조한다. 출처는 `list_followups`, `list_documents`, `read_document`로 고정한다. 저장 문서의 인용은 해당 문서를 이번 확인에서 읽었고 내용 해시와 기록된 출처가 그대로일 때만 채택한다. `saved_document_sources_checked`로 구분해 화면에도 당시 기록임을 표시한다. 이것은 외부 파일의 현재 상태를 재관측한 `cited_sources_rechecked`가 아니며, 외부 읽기 권한을 추가하지 않는다. 향후 추가된 도구나 기존 로컬 자료 승인으로 자동 확장하지 않는다. 중단·불명확한 확인은 자동 재실행하지 않는다. 배경 제안이 없을 때도 실제 사용량은 보존한다.

검증은 실제 SQLite, HTTP, 타이머, 브라우저 JS와 로컬 Telegram 시뮬레이터를 사용한다. 신규 테스트는 명시적 마이그레이션/백업·재시작, 비활성 기본값, 반복/야간 억제, 취소/기기 폐기/새 메시지에 의한 늦은 결과 차단, 모델 호출 한도, 읽기 전용 도구, 조용한 결과, Telegram 연결/복원/해제, 연결 전 사용자 승인과 비밀 비노출을 다룬다. 합성 모델의 문장은 실제 모델의 유용성 증거가 아니다. 실제 소유자 Telegram 연결·휴대폰 송수신·항상 켜진 운영과 제품 평가 16건은 미완료다.
