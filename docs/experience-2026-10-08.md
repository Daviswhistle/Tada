# 사람이 쓰는 Tada로 시작 흐름 다시 만들기

사용자 요청: “사람이 쓰는 프로그램이야 네가 쓰는 게 아니라. 이해하고 있어? 다시 만들어줘.”

기존 구현은 보관 경로, 초기화 여부, 터미널의 YES, 모델 번호, 연결 링크와 기기 이름을 사용자가 관리하게 했다. 기본 시작 흐름을 화면으로 옮기고 연결 이후의 같은 대화·기록·권한 경로를 재사용했다. 따뜻한 문구나 디자인을 능력의 증거로 삼지 않는다.

## 현재 동작

`npm start`는 기본 보관 위치를 선택하고 없을 때만 초기화한다. 기존 디렉터리나 기록을 지우거나 자동 전환하지 않는다. 이전 버전 기록은 화면에서 이유를 설명하고 사용자가 ‘기록 백업하고 업데이트’를 눌렀을 때만 기존 백업 전환 경로로 처리한다. 명시적으로 초기화를 요청했더라도 이번 실행에서 기록 생성이 끝난 뒤 시작에 실패했다면, 화면의 재시도는 생성된 기록을 다시 연다. 생성 전부터 있던 디렉터리를 임의로 새 기록으로 채택하지 않는다. 현재 자동 보호 지원은 Windows/WSL이다. 연결된 계정이 있으면 재사용하고, 없으면 화면에서 데이터 전송 범위를 읽고 ChatGPT 연결 버튼을 누른다. 공식 로그인은 별도 창에서 진행되며 비밀번호나 OAuth 토큰은 시작 화면으로 전달되지 않는다. 계정 모델 목록을 가져와 이름으로 선택하고 다음 실행부터 재사용한다. 실패하거나 취소하면 같은 시작 화면에서 다시 시도한다. 서버가 저장된 인증을 거절하면 재시도는 새 로그인으로 이어지며, 취소한 시작 과정은 대기 업무를 실행하지 않는다. 일시적인 통신 실패는 기존 기기의 재조회로 복구한다.

연결 후 대화 화면으로 이동한다. 기존 브라우저 기기가 유효하면 그대로 사용하며, 최초 기기는 소유자가 연 일회용 링크로 자동 등록한다. 다른 기기의 수동 연결은 유지하되 기기 이름은 기본값으로 진행할 수 있다. 화면의 설정에 계정·사용량·알림·기기 해제를 모으고, 맡긴 일은 펼쳐 보게 했다. 확인이 필요한 제안과 도착한 알림은 접지 않는다.

예시 버튼은 초안만 채운다. Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 보내지 않는다. 전송이 불확실하면 초안을 유지하고 같은 요청 ID로 접수 여부를 확인한다. 실패/중단된 요청은 버튼으로 다시 작성할 수 있으며 작성 중인 새 문장을 덮어쓰거나 자동 실행하지 않는다. 확인된 실패 요청을 사용자가 다시 작성하면 새 요청으로 접수한다. 이때 문장이 같아도 접수 확인 중인 다른 요청의 ID를 바꾸지 않는다. 접수 응답을 기다리는 중에는 재작성을 시작하지 않아 늦은 응답이 복원한 초안을 지우지 않게 한다. 인증된 대화 조회에 원래 요청 ID를 포함해 정확한 요청을 구분한다. 예약 시각은 UTC 오프셋을 함께 표시해 서머타임 종료 때 반복되는 시각도 구분한다. 자료 출처와 실제 지원 범위는 펼쳐서 확인한다.

고급 CLI는 보존한다. 기본 창도 `--data`, `--provider ollama --model ...`, 승인된 자료 범위, 원격 TLS 설정을 기존 계약대로 받는다. 수동 암호 기록·Telegram 설정·로그아웃은 고급 CLI에 남아 있다. 별도 설치 프로그램, 지원되지 않는 OS의 키 보호, 브라우저에서의 자료 선택, 대화 도중의 계정 재연결과 관리 기능 통합은 아직 미완성이다.

## 경계

시작 창은 127.0.0.1의 임시 포트에만 열린다. 256비트 실행별 연결 키를 fragment로 전달하고 즉시 주소창에서 지운다. 브라우저에서는 키를 메모리와 가능할 때 해당 탭의 sessionStorage에 보관한다. 재실행은 데이터 경로별 SQLite 소유권과 `<data>.app-private/window.json`의 Windows 계정으로 보호된 연결 키를 사용해 기존 시작 창을 찾는다. 이 파일에는 원문 연결 키나 계정 토큰을 저장하지 않는다. 다른 설정으로 실행 중인 호스트를 몰래 재설정하지 않으며, 종료 후에는 다음 실행이 소유권을 얻는다. API는 해당 키·정확한 Host·Origin·요청 형식과 현재 화면 버전을 확인한다. 다른 사이트, 오래된 버튼, 중복 연결 실행을 거절한다. 키나 계정 토큰을 화면 자산·오류 응답에 넣지 않는다.

시작 창에서 다른 로컬 포트의 대화로 이동하는 최상위 공개 문서 요청은 다른 포트나 HTTPS 주소로의 내비게이션도 허용한다. 대화 API의 기존 Origin/기기 인증은 유지한다. 시작 창을 닫아도 호스트가 자동 종료되지 않는다. 동일 설정으로 앱을 다시 실행하면 기존 창으로 돌아간다. 로그인·기록 업데이트 같은 일회성 시작 옵션은 지속 설정 비교에서 제외해 다음 일반 실행을 막지 않는다. 실행 중인 호스트에 새 일회성 작업을 요청하면 재시작이 필요하다고 안내하며 몰래 생략하지 않는다. 시작 창의 보호된 정보 저장이 실패하면 대화 런타임을 시작하지 않고 화면에서 오류를 안내한다. 대화 진입 링크는 시작 화면을 조회할 때 만료·사용 여부를 확인해 새로 발급하되 살아 있는 미사용 링크는 재사용한다. 오래된 시작 링크로 돌아와도 유효한 대화 링크를 받는다. 호스트 종료는 계정·기록·시작 창 소유권을 정리하며 저장된 연결을 다음 시작에서 재사용한다. 사용자의 명시적 로그아웃이나 기기 해제를 대신하지 않는다.

## 검증 해석

자동 검증은 실제 HTTP·SQLite와 합성 OAuth/모델을 사용한다. 시작 화면 권한, 외부 Origin/Host 거부, 오래된 응답 거부, 취소 후 재시도, 기존 CLI와 브라우저 런타임의 연결/재시작을 확인한다. 실제 Chrome에서 시작 화면 → 모델 선택 → 대화, 같은 기기 재사용, 390/1280px 화면, 닫은 창의 결과 복원, 작성 중 문장 보존, 기기 해제와 늦은 응답을 확인한다. 화면 이미지는 직접 검토한다.

실제 ChatGPT 로그인·추론, 실제 휴대폰, 설치 프로그램, 항상 켜진 운영, 일반 업무 실행과 전체 16개 제품 인수 시나리오는 이 검증으로 통과 처리하지 않는다. 변경된 경험도 현재 64회 모델 요청/14KiB 문맥 등의 기존 개발 한도를 따른다. 출시 가능한 완제품이라는 선언은 아니다.
